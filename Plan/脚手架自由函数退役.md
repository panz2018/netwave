# 脚手架自由函数与 `Network` 类退役（交接计划）

> **本文件已被本轮研究重写。** 旧版假设「`Network` 保留、新增
> `toBuffer()`/`buffer` setter + `Arc` 引用计数」承接零拷贝证据。本轮核实
> `Touchstone` 已完整吞并 `Network`，用户拍板改为：**自由函数与 `Network`
> 类全部退役，公开面只剩 `Touchstone`，且不新增任何 `Touchstone` 属性/函数**。
> 旧版的 `toBuffer()`/`buffer` 方案作废；`Arc` 机制仅在「node 端 `s` 改零拷贝」
> 这一个决定下才需要（见[待决 D1](#待决需用户拍板)），且从 `Network` 迁移到
> `Touchstone`。下一个接手者：先读本页「已核实事实」与「待决」，再按
> [接手步骤](#接手步骤建议)推进。

## 一句话目标

删除 `fill_pattern` / `read_element` 自由函数与整个 `Network` 类（core +
node + Python + 浏览器四端），零拷贝证据迁移到既有 `Touchstone.s`，
**不新增任何 `Touchstone` 公开面**。

## 已核实事实（带出处，接手者无需重复验证）

- **`Touchstone` 已含 `Network` 全部状态**：`core/src/touchstone.rs:197`
  字段 = `frequency`（`Frequency` 轴）+ `s`（交错 f64 主数据）+ `z0` +
  `nports`/`name`/`comments`/`version`/`parameter`。`Network` 是它的真子集。
- **core `Touchstone::s()` 借用零拷贝**：`core/src/touchstone.rs:767`
  返回 `&self.s`（`&[f64]`），不复制。
- **Python `Touchstone.s` 已是零拷贝活证据**：`python/src/lib.rs:428`
  用 `PyArray3::borrow_from_array(&view, obj)`，base object = pyclass 本身，
  `owndata=False`。写回证据无需 `read_element`：改视图后重读 `ts.s`
  （同一块内存）即可断言可见——**纯用既有 `s`，零新函数**。
- **Python `Touchstone.drop()` 只封存不清 buffer**：`python/src/lib.rs:606`
  仅 `self.1 = true`；`:344` 注释明说「already-acquired views stay valid
  (the buffer is never cleared; the pyclass owns it and numpy's base
  reference keeps it alive)」。**旧版担心的「drop 后视图悬垂」在
  `Touchstone` 上本就不成立，无需 `Arc`。**
- **node `Touchstone.s` 当前是拷贝**：`typescript/native/src/lib.rs:341`
  `Float64Array::from(self.core()?.s().to_vec())`。node `drop()` 同样只封存
  （`:487` `self.1 = true`）。→ 这是唯一真正的待决点（D1）。
- **浏览器 `Touchstone.s` 经拷贝 + 结构化克隆过界**：`core/src/touchstone.rs:1378`
  `f64_array` 把 `&[f64]` 包成 `Float64Array`，worker 回消息时结构化克隆
  再拷一次。浏览器本就无共享内存（transfer 模型），无悬垂问题。
- **`upload` 是 `Network` 专属**：`core/src/network.rs:141`、
  `typescript/src/index.browser.ts:110`。`Touchstone` 的浏览器数据入口是
  `fromBytes`（transfer，`core/src/touchstone.rs` 的 `call_namespace`
  `"fromBytes"` 臂）。**退役 `Network` = 全仓删除 `upload` 概念。**
- **`check_verbs.py` 三处绑定 `Network`**：`NETWORK_VERBS = {fillPattern,
readElement, drop}`（:36）、`BROWSER_ONLY = {upload}`（:83 段）、
  三端 `Network` 类校验段（:209–:242）。
- **`cross_compare.py` 主对比是 scaffold `.bin`**：`core.bin`/`python.bin`/
  `node.bin`/`wasm.bin`（来自 `fill_pattern`/`Network.fillPattern`/`readElement`）。
  **Touchstone 四端对比已独立存在**（`{end}_ts_{s1p,s2p,s4p}*.bin`，
  见 `scripts/cross_compare.py` 的 TOUCHSTONE PASS 段）——scaffold 对比与
  之冗余（见待决 D2）。

## 待决（需用户拍板）

### D1 — node 端 `Touchstone.s` 是否改零拷贝（本计划唯一真正的成本项）

现状：node `s` 拷贝（`typescript/native/src/lib.rs:341`
`Float64Array::from(...s().to_vec())`）。scaffold 的 `_readElement` 是 node
端唯一的「同一块内存」活证据，退役后若不处理，node 失去零拷贝证明，
[zero-copy-roundtrip spec](../openspec/specs/zero-copy-roundtrip/spec.md)
的「Node 视图零拷贝且可写回 core」scenario 落空。

- 选项 A（保零拷贝，推荐）：core `Touchstone.s` 字段 `Vec<f64>` →
  `Arc<Vec<f64>>`，node `get_s` 改 `ArrayBuffer::from_external` + finalize
  回调 drop Arc clone（napi-rs 实证模式，旧版「三家实证」节仍有效）。
  这是**改既有 getter 实现**，`.d.mts` 签名仍是 `Float64Array`，不新增名字，
  符合「不增加属性和函数」。Python 端 `s` 已零拷贝，无需动。
- 选项 B（node 保持拷贝）：零拷贝证据只留 Python（numpy/skrf 互操作是
  铁律一的正牌卖点）；zero-copy-roundtrip spec 出 delta 删 node 零拷贝
  scenario。代价：削弱一条已文档化的跨端保证。

### D2 — scaffold 四端对拍是否被 Touchstone 对拍完全取代

倾向已定：是。`scripts/cross_compare.py` 的 scaffold 段
（`core.bin`/`python.bin`/`node.bin`/`wasm.bin`）与既有 Touchstone 段
（`{end}_ts_{s1p,s2p,s4p}*.bin`）覆盖同样四端、且用真实数据更强。退役即删
scaffold 段 + 四端 dump 脚本里的 scaffold dump 行。**必做连带**：
anti-tautology 自检当前扰动 python/node/wasm `.bin`，须改扰 `_ts_*` bin，
否则自检失效。

### D3 — `upload` 退役后的「显式托管入口」归属

`upload` 随 `Network` 删除。浏览器数据入口改由 `Touchstone.fromBytes`
（transfer `Uint8Array`）/`fromFile`/`fromUrl` 承担。**接手者须先核实**
浏览器壳 `fromBytes`/`fromFile` 确以 transfer list 移交输入 buffer
（`typescript/src/index.browser.ts` 的 Touchstone 工厂），再据此改
[api-contract spec](../openspec/specs/api-contract/spec.md)
「显式托管入口与显式内存回收」requirement 与铁律八 scenario 的措辞
（旧文以 `Network.upload` 举例）。

### D4 — memory-lifecycle「显式 `drop()` 确定性即时」对 `Touchstone` 的措辞

`Touchstone.drop()` 三端只封存实例（访问报错），物理内存随包装器 GC/RAII
散场（Python `python/src/lib.rs:606` 仅置标志，buffer 不清）。这与
[memory-lifecycle spec](../openspec/specs/memory-lifecycle/spec.md)
「调用后 MUST 不依赖 GC 即时触发 Rust `Drop`」字面冲突。接手者须核实
`Touchstone` 当前实现是否已被该 spec 容忍；若否，出 delta 把「即时」限定为
「实例封存即时，物理回收随最后一个持有者散场」。`live_count()` 维持
`Frequency` 专属，`Touchstone` 以访问报错为见证，不新增计数器。

### D5 — 浏览器「零拷贝视图」scenario 的归宿

常驻 worker 架构后主线程无 wasm，「视图 buffer 即 wasm `Memory.buffer`」
在物理上不可能。zero-copy-roundtrip spec 的 wasm scenario 早于该架构、
疑已陈旧。接手者核实后：浏览器往返测试改断言 transfer/结构化克隆路径的
**数据正确性**（非「零拷贝视图」），spec 出对应 delta。

## 已定（用户本轮拍板 + 研究确认）

1. **`Network` 类整体删除**（core + 三端绑定 + 壳 + 测试），数据状态类唯一
   为 `Touchstone`。`fill_pattern`/`read_element` 自由函数一并删。
2. **不新增任何 `Touchstone` 公开属性/函数**——零拷贝证据全部复用既有
   `s`（读）+ 工厂（写/构造）。旧版 `toBuffer()`/`buffer` setter 方案作废。
3. **`Arc` 机制仅在 D1 选 A 时启用**，且落在 `Touchstone.s` 字段，不落
   `Network`（`Network` 已不存在）。
4. **`drop()` 三端保留**（铁律十二同名；浏览器端它是 worker 表释放的唯一
   通道，删了必泄漏）。

## 零拷贝证据迁移（三端，全用既有面）

| 端     | 构造（数据入口）                           | 零拷贝/往返证据（既有面）                                            | 新增面 |
| ------ | ------------------------------------------ | -------------------------------------------------------------------- | ------ |
| Python | `Touchstone.from_file` / `Touchstone(...)` | `ts.s`（`owndata is False`）改写后**重读 `ts.s`** 断言可见           | 无     |
| node   | `new Touchstone(...)` / `fromFile`         | 取决于 D1：A→`ts.s` external 视图改写重读；B→仅验数据正确            | 无     |
| 浏览器 | `Touchstone.fromBytes`（transfer）         | `await ts.s` 经常驻 worker 往返，断言数据正确（非零拷贝视图，见 D5） | 无     |

写回证据不再需要 `read_element(view, idx)` 把视图传回 Rust：Python 改视图
后重读 `ts.s` 即同一块内存（base=pyclass，已核实）。
