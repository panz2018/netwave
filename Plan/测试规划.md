# NetWave 测试规划

> 核心思想：**scikit-rf 是数值 oracle，但 CI 不跑 Python**——用离线生成的 golden
> 文件把 Python 从测试关键路径上摘出去；跨绑定用同一 core 互相对拍。
> 精度分层契约见[铁律三](../openspec/specs/project-governance/spec.md)，
> testdata 目录布局见 [testdata/README.md](../testdata/README.md)。

## 测试分层总览

四层按**执行顺序**排列（从内到外、从便宜到贵），CI 依此顺序执行、先失败先短路。
分层不设编号，正式名称即下表第一列——CI job 名、测试目录名、PR 标签直接用：

| 顺序 | 层名                            | 内容                              | 依赖                               | 运行位置        | 容差来源                                  |
| ---- | ------------------------------- | --------------------------------- | ---------------------------------- | --------------- | ----------------------------------------- |
| 1    | **unit**（单元测试）            | 闭式解自校验 + 边界情况，固定样本 | 无                                 | `cargo test`    | [manifest](#manifestjson-契约) `core_tol` |
| 2    | **property**（属性测试）        | proptest 随机不变量               | 无                                 | `cargo test`    | [manifest](#manifestjson-契约) `core_tol` |
| 3    | **golden**（金标准测试）        | 与 skrf 预生成结果比对            | [testdata/](../testdata/README.md) | 四端各自 runner | manifest 各 case `tol_abs`/`tol_rel`      |
| 4    | **cross-binding**（跨绑定对拍） | core/python/node/wasm 互比        | 无                                 | CI              | 原生三端 bit 级；wasm `tol_rel`（铁律三） |

unit + property 在 Rust core 内，完全不碰外部；golden 锚定"与 skrf 数值一致"；
cross-binding 抓绑定层胶水 bug（字节序、形状转置、零拷贝视图错位）。

## unit —— 单元测试（解析自校验）

教科书有闭式解的电路直接手算比对。放 `core/src/**/tests.rs` 或 `core/tests/`。
容差一律从 manifest `core_tol` 读取（铁律三），测试代码禁止字面量容差。

### 变换恒等类

- `S → Z → S`、`S → Y → S`、`S → T → S` 往返恒等（`core_tol.roundtrip`）
- `se2gmm → gmm2se` 往返恒等（mixed-mode）
- renormalize 到原 z0 应恒等
- `renumber` 后再按逆置换 renumber 应恒等

### 已知解析解类

- **λ/4 阻抗变换器**：闭式反射/传输直接断言
- **理想 Thru**：`S = [[0,1],[1,0]]`，级联任意网络应还原该网络
- **理想匹配负载**：`S11 = 0`
- **理想功分器 / Wilkinson**：旧库 `designer_wilkinson_splitter.s3p` 作输入
- **无损线时延**：`S21 = exp(-jβl)`，端口延时应精确抵消

### 物理不变量

- 互易网络 `S = Sᵀ`；无源网络最大奇异值 ≤ 1；无损网络 S 酉 `SᴴS = I`；
  因果性：时域冲激响应 t<0 部分能量 ≈ 0

### Touchstone 解析边界

- 1.0 / 1.1 语法、RI / MA / DB 三格式、频率单位前缀
- `!` 注释、`#` 选项行、`R` 参考阻抗（标量/每端口/复数）
- 噪声数据行（`[Number of Noise Frequencies]`）
- 缺列 / 多余空白 / CRLF / 无尾换行 / 科学计数法 / 负零
- 1 端口到 32 端口（旧库 `ntwk.s32p`）
- 写出→读回 **bit 级一致**（shortest-roundtrip 格式化，断言 `==`）

## property —— 属性测试（proptest）

随机生成**合法** Network，断言不变量；helper 启动时读一次 manifest 注入 `TOL`。
关键属性清单：

- 参数往返恒等（S↔Z/Y/T/H/G）
- 级联维度正确、级联恒等（∘ Thru）
- renumber 是置换（保多重集）
- Touchstone 写出→读回恒等（bit 级）
- passivity 在级联下保持
- FFT 时域→频域往返恒等

## golden —— 金标准测试（skrf oracle）

### golden 生成（`testdata/gen_golden.py`）

唯一运行 Python 的地方，**离线、按需、不进主 CI**（铁律四）。环境 uv 管理
（`pyproject.toml` + `uv.lock` 钉死 skrf/numpy，跑法 `uv run python gen_golden.py`）。

- 输入样本：skrf 自带测试集（BSD-3，保留版权头）+ 旧库
  `RF-Touchstone/test/samples/`（自产 MIT）；入库逐文件登记
  `testdata/LICENSE-NOTES.md`（见 license-compliance spec）
- 覆盖操作：parse、S↔Z/Y/T/ABCD、cascade、deembed、renumber、mixed-mode、TDR
- 每操作多个端口数/格式样本；边界（复数 z0、非 50Ω）单独造
- 产物：交错复数 f64 裸二进制（小端），提交进 git

### manifest.json 契约

三端 runner 唯一输入清单，**精度标准集中在此**（铁律三）。schema 要点：

- `core_tol`：unit/property 层默认容差；
- `output_kind`：`complex`（交错 f64）/ `float` / `int`，golden 二进制按此解释；
- `input_kind`：`committed`（进 git）/ `generated`（CI 内生成，如 50MB 大文件）；
- `tol_abs`/`tol_rel`：wasm 类用例只声明 `tol_rel`（绝对容差在大值上误报）；
- 比对统一 `max(abs_diff, rel_diff*scale) < tol`。

### 三端 runner（薄，只读数据 + 断言）

| 端     | 位置                            | 读 golden 方式              |
| ------ | ------------------------------- | --------------------------- |
| Rust   | `core/tests/golden.rs`          | `std::fs::read` → `&[f64]`  |
| Python | `python/tests/test_golden.py`   | `np.fromfile(dtype='<c16')` |
| Node   | `typescript/test/`              | `new Float64Array(buf)`     |
| WASM   | `typescript/test/`（wasm 项目） | 同 Node                     |

### skrf 升级守护

独立 workflow `golden-refresh.yml` 每周重生成 + `git diff`；有 diff 开 issue
人工确认；主 CI 永不跑 Python。

## cross-binding —— 跨绑定一致性对拍

四端委托同一份 Rust 算法，断言强度按铁律三：**同机同架构原生三端 bit 级互比；
wasm 跨编译目标用 manifest 相对容差**（典型 `core_tol` 1e-14，多数用例仍 bit 级
命中，SIMD 路径容差通过即正常）。CI 单 job 构建四端后跑同一组用例；本地跑法见
[CONTRIBUTING.md](../CONTRIBUTING.md) `pnpm check:cross`。

## 性能基准（criterion）

| 基准                    | 目标                  |
| ----------------------- | --------------------- |
| 解析 50MB s4p           | < 100ms（铁律六底线） |
| S→Z（1001 点 × 4 端口） | < 5ms                 |
| 级联 1000 次            | < 50ms                |
| FFT 时域 1M 点          | < 200ms               |

- CI 跑 criterion，显著劣化（>20%）失败（铁律六）；
- 大文件样本脚本生成，不提交超大文件。

### 基线跨提交持久化（阶段 2 任务）

GitHub Actions runner 每次干净，`target/criterion/` 不跨 run 保留——当前 bench
job 只能测同机噪声。阶段 2 改造为"基线提交进仓库"：

- CI 跑 `cargo bench -- --baseline=<仓库基线名>`，`change/estimates.json`
  导出到仓库内 `benches/baseline/` 提交（commit message 标注来源与 runner）；
- 命名空间隔离：CI 只用 `ci`，本地只用 `local`（`target/` gitignore）；
  门禁脚本只读仓库里那份 CI 基线；
- 性能变化随 PR diff 可见——与 manifest 同一套治理思路。

## 覆盖率标准

**全端 100% 行覆盖，unit 层零豁免**（铁律七）；唯一例外为结构性不可达代码，
逐条标注豁免并登记理由（`#[coverage(off)]` / `# pragma: no cover` /
`/* v8 ignore start/stop */`），禁止整文件/整目录批量豁免。工具与门槛：
`cargo llvm-cov`、`pytest-cov`、vitest v8 `lines/branches: 100`、clippy、fmt。
具体命令行见 [CONTRIBUTING.md](../CONTRIBUTING.md) 与各子 README。

100% 是**下限不是目标**：执行到 ≠ 断言对，数值正确性由 golden/property/
cross-binding 负责。

| 6 绑定高级能力  | GIL/AsyncTask 并发正确性、wasm 视图失效强制机制测试、CSV 往返、覆盖率达标                   |
| 7+ 高级功能     | 每新模块补 unit + property + golden（四端），golden 增量生成                                |
