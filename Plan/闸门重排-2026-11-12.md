# 测试闸门统一与重排（2026-11-12）

状态：**待逐条点名执行**。本档汇总一次 CI 失败的根因分析、CI 命令全景、
任务分解与全部待拍板决策；后续按任务逐个讨论、执行、修改。

## 1 背景：一次 CI 红暴露的口径裂缝

- CI run 43141529804（#182，`init` 分支）8 个失败 job 同一根因：
  `typescript/src/index.browser.ts` 第 252 行 `nports ?? null` 分支在 wasm
  测试中从未执行（branch 95.83% < 100% 地板），本地已复现。
- 两层根因叠加：
  1. 根 `pnpm check` 不含任何测试（`check:ts` 仅 biome lint）；
     vitest / pytest / 覆盖率 100% 闸门**只存在于 CI**，本地无聚合入口。
  2. tasks.md 的验证命令手抄 CI 参数且抄漏：归档 change
     `add-bytes-io-encoding` 任务 4.1 写的是裸 `pnpm -C typescript test:wasm`，
     CI 实跑 `test:wasm --coverage`。裸跑全绿、覆盖率红——口径漂移不可见。

结构性事实：ci.yml 头部注释已定原则——"命令细节唯一真相源在根
package.json，CI 只调用"。lint job 遵守了；**全部测试步骤却是内联手抄**。
这就是假绿的土壤：本地没有全量测试入口，tasks.md 只能手抄 CI 参数，
抄漏 `--coverage` 就看不见分支缺口。

## 3 目标与不变式

- **本地与 CI 同口径**：同一命令同一参数，理想情况是同一串字面。
- **命令细节唯一真相源 = 根 package.json**（把 ci.yml 头部既有原则
  贯彻到测试步骤）。
- 功能只增不减。
- 每个任务独立可验证、独立可回滚。

## 5 待拍板决策（各方观点与推荐）

### 决策一 rust 测试与覆盖率：拆两条、合并、还是全平台

事实（已实证）：

- llvm-cov 做插桩时**会执行测试**——linux-x64 格 CI 现在把 core 测试跑了
  两遍（`cargo test` + `llvm-cov`），冗余真实存在；python/node 端本来就是
  一条命令"测试+阅卷"（pytest --cov / vitest --coverage）。
- `cargo test --workspace` 的独有价值：四平台跑 core 测试；host 目标编译
  三个绑定 crate 与 examples（绑定 crate 无 `#[test]`，价值是编译闸门；
  其中 wasm crate 的 host 编译无其他覆盖者）。
- `llvm-cov -p netwave` 不编译另外三个 crate。
- cargo-llvm-cov 经 cargo install 源码编译，每格约数分钟。
- 100% 地板在 linux 标定：覆盖率数字受平台影响（内联决策、cfg 编译面、
  OS 相关分支），换平台跑同一门槛可能出现"代码没问题、数字差 0.x%"的
  假红；仓库已被同类假红咬过（`--fail-under-lines` 恒 99.x% 问题）。

选项：

- **甲** 拆两条：`test:rs`（全平台）+ `test:rs:cov`（仅 linux）。
  现状口径，最小改动；linux 双跑冗余保留。
- **乙** 单命令全平台覆盖率：与其他语言口径一致；代价 = 每格多几分钟
  编译安装 + 假红风险，须先全平台跑数字、调平后才启用 100% 地板。
- **丙** linux 格合并（`test:rs:cov` 替代 `test:rs`），其余平台
  `test:rs`：消掉双跑；代价 = CI 保留步骤级 if（本来就有），
  本地行为随机器不同。

推荐：**甲为基线**（最小改动、不引入新假红面）；若愿意付标定成本，
乙是与其他语言口径最一致的终态；丙可作甲之后的优化项。

### 决策二 `check:cross` 是否改名 `test:cross`

事实：grep 命中 72 处，其中约 30 处在归档 change（冻结历史，不改）；
活文档约 15 个文件（根 package.json、ci.yml、CONTRIBUTING、
oracle/README、scripts/README、check_verbs.py、check_vocab_types.py、
dump.mjs、dependency-upgrade spec、project-governance spec、账本四分片、
Plan/测试规划）。

- **甲** 保名：`test:cross` = 前置（maturin/stub_gen）+ 调 `check:cross`。
  零波及，但 `check:*` 家族里混着一个要跑四端代码的异类。
- **乙** 改名：分类更干净——`check:*` = build-free 静态检查，
  `test:*` = 跑代码的闸门；`check:cross` 跑四端 dump，本属测试性质。
  代价 = 约 15 个活文件一次波及同步（含两份 spec，须一个 change 内改全，
  归档保持冻结）。

推荐：**乙**（命名一致性有长期价值，成本一次性且可枚举）；
若想压缩单轮范围，可先甲、改名另立小 change。

### 决策三 聚合命令硬编码 `--coverage`

聚合入口一律带覆盖率（绿 = CI 口径全过）；快循环直接用 typescript 现成
裸 `test:*`，不给聚合入口留"不带覆盖率"的口子。推荐：是。

### 决策四 前置工具缺失：报错提示、不自动安装

`test:rs:cov` 要 cargo-llvm-cov、`test:ts` 要 wasm-pack/binaryen/Chromium、
`test:py` 要 maturin。脚本开头探测，缺则报错并打印对应安装命令
（`scripts/install_cargo_llvm_cov.sh`、`scripts/install_*.sh`、
`playwright install --only-shell chromium`），不自动安装（机器副作用；
CI 自带安装步骤）。推荐：是。

### 决策五 bench 不进聚合（已定）

人工裁决：bench 未完成（基线持久化未落地，现仅测噪声），本轮不动，
完工后再议。

### 决策六 dts 防 `any` 闸门归 `test:ts`，不归 `check:ts`

lint job 是 build-free by design（秒级反馈、不装 wasm 工具链）；
dts 检查对象 `dist/*.d.mts` 必须先 build:wasm + build:native 才存在。
塞进 `check:ts` 会逼 lint job 背全套工具链。位置 = `test:ts` 内 build
之后（与 tsc typecheck 同段）。推荐：是（即 T3）。

### 决策七 check_ci.py 升级口径

根 package.json 每条 `test:*`（含多段名）MUST 出现在 ci.yml——
"CI 不跑的测试不算闸门"（LL-037）从 typescript 级升到根级；
typescript 级旧规则退役。推荐：是（即 T4）。
