# NetWave 测试规划

> 核心思想：**scikit-rf 是数值 oracle，golden 由 CI 在 oracle 的 uv 环境现算、
> 不入库**——skrf 圈禁于 oracle 环境，各端测试关键路径零 Python；跨绑定用
> 同一 core 互相对拍，阅卷集中在 `oracle/compare_cross.py`。
> 精度分层契约见[铁律三](../openspec/specs/project-governance/spec.md)，
> oracle 目录布局见 [oracle/README.md](../oracle/README.md)。

## 测试分层总览

四层按**执行顺序**排列（从内到外、从便宜到贵），CI 依此顺序执行、先失败先短路。
分层不设编号，正式名称即下表第一列——CI job 名、测试目录名、PR 标签直接用：

| 顺序 | 层名                            | 内容                              | 依赖                   | 运行位置       | 容差来源                                  |
| ---- | ------------------------------- | --------------------------------- | ---------------------- | -------------- | ----------------------------------------- |
| 1    | **unit**（单元测试）            | 闭式解自校验 + 边界情况，固定样本 | 无                     | `cargo test`   | [manifest](#manifestjson-契约) `core_tol` |
| 2    | **property**（属性测试）        | proptest 随机不变量               | 无                     | `cargo test`   | [manifest](#manifestjson-契约) `core_tol` |
| 3    | **golden**（金标准测试）        | 与 skrf 现算结果比对              | oracle uv 环境（skrf） | CI oracle 步骤 | manifest 各 case `tol_abs`/`tol_rel`      |
| 4    | **cross-binding**（跨绑定对拍） | core/python/node/wasm 互比        | 无                     | CI             | 原生三端 bit 级；wasm `tol_rel`（铁律三） |

unit + property 在 Rust core 内，完全不碰外部；golden 锚定"与 skrf 数值一致"；
cross-binding 抓绑定层胶水 bug（字节序、形状转置、零拷贝视图错位）。

## unit —— 单元测试（解析自校验）

教科书有闭式解的电路直接手算比对。放 `core/src/**/tests.rs` 或 `core/tests/`。
容差为测试自述常量（铁律三：core 内部测试与 oracle 零依赖；跨端阅卷容差唯一
存 `oracle/manifest.json`，只服务阅卷脚本）。

### 变换恒等类

- `S → Z → S`、`S → Y → S`、`S → T → S` 往返恒等（`core_tol.roundtrip`）
- `se2gmm → gmm2se` 往返恒等（mixed-mode）
- renormalize 到原 z0 应恒等
- `renumber` 后再按逆置换 renumber 应恒等

### 已知解析解类

- **λ/4 阻抗变换器**：闭式反射/传输直接断言
- **理想 Thru**：`S = [[0,1],[1,0]]`，级联任意网络应还原该网络
- **理想匹配负载**：`S11 = 0`
- **理想功分器 / Wilkinson**：旧库 `designer_wilkinson_splitter.s3p` 作输入
- **无损线时延**：`S21 = exp(-jβl)`，端口延时应精确抵消

### 物理不变量

- 互易网络 `S = Sᵀ`；无源网络最大奇异值 ≤ 1；无损网络 S 酉 `SᴴS = I`；
  因果性：时域冲激响应 t<0 部分能量 ≈ 0

## property —— 属性测试（proptest）

随机生成**合法** Network，断言不变量；容差为测试自述常量（铁律三容差分层）。
关键属性清单：

- 参数往返恒等（S↔Z/Y/T/H/G）
- 级联维度正确、级联恒等（∘ Thru）
- renumber 是置换（保多重集）
- Touchstone 写出→读回恒等（bit 级）
- passivity 在级联下保持
- FFT 时域→频域往返恒等

## golden —— 金标准测试（skrf oracle）

### samples 样本精选（v1.x 跨端输入集）

27 个。经逐文件核实选项行后精选 17 个进 `oracle/samples/`，每个文件至少
扛一个独有维度，矩阵全覆盖。目录**平铺一层**、文件名**原样保留**（大写扩展名、

默认全覆盖。**Y/G 域**：两仓现成文件为 0，也**不造转换另存的第二份数据文件**——
Y/G/H 的数值覆盖由 golden 生成链直接从 S 文件生成数值矩阵完成（见

rf-touchstone 旧仓库自有测试文件，**不登记 LICENSE-NOTES**。已知排除（均不进
samples，由 unit 层内联文本覆盖）：`skrf/io/tests/double_option_line.s2p`
（双选项行 + 复数 R 非法输入，解析直接报错）；噪声文件（当前不支持，四端报错
一致性待有需求再议）；v2.x 文件（独立路线图项，本轮纯 v1.x）。

### golden 生成（`oracle/gen_golden.py`，下期）

唯一运行 skrf 的地方，**CI 现算、golden 不入库**（铁律四）。环境 uv 管理
（`oracle/pyproject.toml` + `oracle/uv.lock` 钉死 skrf/numpy）。

- 输入样本：skrf 自带测试集（BSD-3，保留版权头）+ 旧库
  `RF-Touchstone/test/samples/`（自产 MIT）；入库逐文件登记
  `oracle/LICENSE-NOTES.md`（见 license-compliance spec）
- 覆盖操作（当前范围 = 解析 + 域/格式换算）：每个输入文件生成
  S/Z/Y/G/H 域 × RI/MA/DB 格式的数值矩阵 golden；G/H 仅 2 端口有定义，
  > 2 端口文件跳过 G/H。**文件 × 支持组合全覆盖，不挑子集**。ABCD、cascade、
  > deembed、renumber、mixed-mode、TDR 当前 netwave 不支持，对应 golden 待
  > 计算功能落地后再加
- 边界（非 50Ω）用已有文件；复数 z0 规范禁止、不造
  （见[解析覆盖契约](../openspec/specs/touchstone-core/spec.md)）
- 产物：交错复数 f64 裸二进制（小端），只活在 `oracle/tmp/golden/`，
  **不提交 git**（bin 在 git 中不可审计，维护数据变更负担大于收益）

### manifest.json 契约

跨端阅卷脚本唯一输入清单，**跨端阅卷容差集中在此**（铁律三；core 内部测试
容差为测试自述常量，不读本文件）。schema 要点（`schema_version=1` 为下期规划，
当前 manifest 为 `schema_version=0` 骨架）：

- `core_tol`：跨端阅卷容差（wasm 相对容差唯一来源）；
- `sha256`：每个 committed 输入文件的指纹，四端 runner 解析前先校验，
  不匹配立即失败（防数据静默漂移）；
- `output_kind`：`complex`（交错 f64）/ `float` / `int`，golden 二进制按此解释；
- `input_kind`：`committed`（进 git）/ `generated`（CI 内生成，如 50MB 大文件）；
- `tol_abs`/`tol_rel`：wasm 类用例只声明 `tol_rel`（绝对容差在大值上误报）；
- 比对统一 `max(abs_diff, rel_diff*scale) < tol`。

### 阅卷集中（各端只 dump 不比较）

横向轴阅卷在 `oracle/compare_cross.py`（纯标准库）：四端把计算结果 dump 到
`oracle/tmp/<end>/<sample>/<field>.bin`，由阅卷脚本统一读取比对；各端测试内
MUST NOT 做跨端比较。golden 纵向轴同理集中到 `oracle/compare_golden.py`
（下期），不在各端测试内。

### skrf 升级守护

skrf 版本靠 `oracle/uv.lock` 钉死，升级 = 显式改 lock 的 PR（标准版本化由
lock 承担）。周更 `golden-refresh.yml` workflow 作废——golden 不入库，没有
可 diff 的提交数据，不再做数据变更审计。

## cross-binding —— 跨绑定一致性对拍

四端委托同一份 Rust 算法，断言强度按铁律三：**同机同架构原生三端 bit 级互比；
wasm 跨编译目标用 manifest 相对容差**（`core_tol.relative`，多数用例仍 bit 级
命中，SIMD 路径容差通过即正常）。CI 单 job 构建四端后跑同一组用例，阅卷在
`oracle/compare_cross.py`；本地跑法见
[CONTRIBUTING.md](../CONTRIBUTING.md) `pnpm check:cross`。

## 性能基准（criterion）

| 基准                    | 目标                  |
| ----------------------- | --------------------- |
| 解析 50MB s4p           | < 100ms（铁律六底线） |
| S→Z（1001 点 × 4 端口） | < 5ms                 |
| 级联 1000 次            | < 50ms                |
| FFT 时域 1M 点          | < 200ms               |

- CI 跑 criterion，显著劣化（>20%）失败（铁律六）；
- 大文件样本脚本生成，不提交超大文件（固定随机种子保证字节可复现、计时可比；
  具体生成参数与计时方法待实施时另议）。

### 基线跨提交持久化（Touchstone 核心期任务）

GitHub Actions runner 每次干净，`target/criterion/` 不跨 run 保留——当前 bench
job 只能测同机噪声。Touchstone 核心期改造为"基线提交进仓库"：

- CI 跑 `cargo bench -- --baseline=<仓库基线名>`，`change/estimates.json`
  导出到仓库内 `benches/baseline/` 提交（commit message 标注来源与 runner）；
- 命名空间隔离：CI 只用 `ci`，本地只用 `local`（`target/` gitignore）；
  门禁脚本只读仓库里那份 CI 基线；
- 性能变化随 PR diff 可见——与 manifest 同一套治理思路。

## 覆盖率标准

**全端 100% 行覆盖，unit 层零豁免**（铁律七）；唯一例外为结构性不可达代码，
逐条标注豁免并登记理由（stable 通道 `#[cfg(not(coverage))]` / `# pragma: no cover` /
`/* v8 ignore start/stop */`；`#[coverage(off)]` nightly-only 禁用），禁止整文件/整目录批量豁免。工具与门槛：
`cargo llvm-cov -p netwave`、`pytest-cov`、vitest v8 `lines/branches: 100`、clippy、fmt。
具体命令行见 [CONTRIBUTING.md](../CONTRIBUTING.md) 与各子 README。

100% 是**下限不是目标**：执行到 ≠ 断言对，数值正确性由 golden/property/
cross-binding 负责。
