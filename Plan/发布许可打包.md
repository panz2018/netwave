# 发布时许可打包（publish 流水线任务）

license-compliance spec 要求所有发布物（crate、wheel、npm 包）随附
`LICENSE-MIT` 与 `LICENSE-APACHE` 两份许可全文。许可全文只存仓库根
（单一真相源），而各打包工具的许可字段都只认**包目录内**的文件，
故需在发布流程统一 copy。当前未到发布阶段，本文件登记待办。

## 各端现状与限制

- **npm（typescript/）**：已解决——`publish_shell.mjs` 在构建时把根两份
  许可 copy 进包目录，`package.json` 的 `files` 列出两者。
- **cargo crate（core、python、typescript/native、typescript/wasm）**：
  `license-file` 只接受单个路径（list 会让 `cargo metadata` 失败），
  现指向 `../LICENSE-MIT`，`.crate` 内只有 MIT，缺 Apache 全文。
  且 `license` 与 `license-file` 并存，cargo 已持续告警
  "only one of license or license-file is necessary"。
- **Python wheel（python/）**：`license-files` 的 glob 相对
  `pyproject.toml` 所在目录，`../` 不可用；现 wheel 内两份许可均缺。

## 待执行（发布流水线立项时）

1. 新增 `scripts/prepare_publish.sh`：把根 `LICENSE-MIT`、`LICENSE-APACHE`
   copy 进 `core/`、`python/`、`typescript/native/`、`typescript/wasm/`
   （与 npm 端 `publish_shell.mjs` 的做法对齐）。
2. 各 crate manifest：`license-file` 改指包内文件并纳入 `include`；
   删除 `license` 与 `license-file` 并存告警（保留 SPDX `license`
   即可表达 MIT OR Apache-2.0，许可全文由 copy + include 保证随包）。
3. `python/pyproject.toml`：copy 后启用
   `license-files = ["LICENSE-MIT", "LICENSE-APACHE"]`。
4. `scripts/check_license.py` 加闸门：发布准备后校验各包目录内
   两份许可文件存在且内容与根一致，防止 copy 步骤被绕过。
5. 发布 CI（release workflow，届时立项）：publish 前强制跑
   `prepare_publish.sh` + 上述校验。

## 禁用方案

- git 符号链接：Windows 检出（`core.symlinks=false`）会把软链变成
  含路径的文本文件并静默打进发布物——CI 含 windows 格，不可接受。
