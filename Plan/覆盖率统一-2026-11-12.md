### wasm 壳 functions 阈值是否补卡（待点名）

- 现状：`vitest.wasm.config.ts` 的 coverage 阈值只卡 `lines: 100` 与
  `branches: 100`，**未卡 `functions`**。实测 `src/index.browser.ts`
  在 wasm 套件下 functions 为 56/57（98.24%），唯一未覆盖函数是
  `Touchstone.fromUrl` 的 `.then((handle) => new Touchstone(handle))`
  成功回调（`index.browser.ts` line 275）。
- 该回调**已被真实浏览器套件覆盖**（`test/browser/browser-fromurl.test.ts`
  走同源 vite 服务器让 worker 的 `web_sys::fetch` resolve）；node 下无同源
  HTTP 服务器，fetch 成功路径不可达，故 wasm 套件单独跑时该函数计数为 0。
- 待决：是否给 wasm 配置补 `functions: 100`。补了会因上述跨套件分工而
  失败（除非把 fromUrl 成功路径也搬进 wasm 套件，但 node 无同源服务器做不到），
  故当前不补是有意为之。若将来要求 wasm 单套件 functions 满覆盖，需先解决
  node 端 fetch 成功路径的可达性（如起本地 HTTP fixture server）。
- 验证：补阈值前先 `pnpm test:wasm --coverage` 确认 functions 实际值。
