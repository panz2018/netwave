- **合并**：rust 测试与覆盖率合并为一条命令，不再拆 `test:rs` +
  `test:rs:cov` 两条（人工原话：test:rs:cov 本来就覆盖 test:rs，
  没有必要分开成两个命令）。
- **全平台**：覆盖率四平台都跑，不只 linux（人工原话：有这个能力
  为啥不直接全平台，反正都是要测试的）。
- **扩面**：python/native 的 rust 胶水行覆盖率一起纳入，不再维持
  "测试与覆盖率分离"（人工原话：既然可以补全覆盖率测试，那就一起
  弄了呗）。
- **装工具改下载**：cargo-llvm-cov 不再 `cargo install` 源码编译，
  改下载官方预编译包（人工原话：Q1 可以）。

## 2 已实证事实（出处）

- cargo-llvm-cov v0.9.1 官方 release 提供本仓库全部四平台预编译产物
  （linux x64/arm64、macOS x64/arm64、windows-msvc x64/arm64）
  （github.com/taiki-e/cargo-llvm-cov/releases，2026-11-12 查询）。
- 平台支持：`x86_64-pc-windows-msvc` 官方确认能用；`windows-gnu` 与
  `aarch64-pc-windows-msvc` 不支持——均不在本仓库矩阵内
  （cargo-llvm-cov README「Platform Support」节）。
- 外部测试驱动采集（show-env 流程，README「Get coverage of external
  tests」节）：`show-env` → `clean --workspace` → 插桩 `cargo build`
  → pytest/vitest 照常跑 → `cargo llvm-cov report`。注意：show-env
  环境里除 `report`/`clean` 外的 llvm-cov 子命令不可用。
- WASM 覆盖率：官方仅指向 wasm-bindgen-test 的覆盖率方案
  （README「WASM」节）；本仓库 wasm 测试是 vitest 驱动，插桩计数
  能否倒出**未验证**。
- `core/src/` 无 `cfg(windows)`/`cfg(unix)`/`cfg(target_os)` 平台分支
  （grep 实证）——core 代码四平台同面；换平台数字差异只剩编译器
  内联决策，codecov OR 合并语义（`coverage_gate.py` 现行做法）可消。
- 绑定 crate 形态：python（cdylib+rlib）、native（cdylib+rlib）、
  wasm（仅 cdylib）；三者均无 `#[test]`。
- `python/Cargo.toml` 已有 `cfg(coverage)` 适配（frequency 注册门控）。
- 绑定 crate 中的"纯函数"（如 `filename_from_path`）是一行转发
  core 的管道；真正值得打分的胶水行是 `resolve_freq_unit` 类 match
  臂、drop 守卫、unsafe 零拷贝块——这些由对面（vitest/pytest）驱动
  执行，恰是 show-env 流程能打上分的行。
- ci-matrix spec 铁律七钉死命令字面（`cargo llvm-cov -p netwave` +
  `coverage_gate.py 100`）且明文"绑定 crate 不进 llvm-cov job 属
  工具作用域分离"——扩面 = 修宪，须同一 change 内改 spec。
- `scripts/coverage_gate.py` 现只消费单个 codecov.json 报告。

## 3 任务分解

### S1 rust 测试与覆盖率合并为单命令

- 目标：一条命令消掉 linux 双跑（`cargo test --workspace` +
  `llvm-cov` 各跑一遍 core 测试的冗余）。
- 待定细节：命令构成是否含 `cargo build --workspace --all-targets`
  （三个绑定 crate 无 `#[test]`，其 host 编译闸门今天只靠
  `cargo test --workspace`，llvm-cov `-p netwave` 不编译它们——
  不补 build 则编译坏了没人拦，agent 推荐补）；命令命名
  （`test:rs` 还是 `test:rs:cov`）；与闸门重排档 T1 聚合入口
  `pnpm test` 的接线。
- 验证：本地单命令全绿，core 测试只执行一遍。

### S2 全平台覆盖率标定

- 目标：四平台（linux-x64/arm64、windows-x64、darwin-arm64）都跑
  覆盖率，替代"仅 linux-x64"。
- 待定细节：100% 地板直接启用，还是先跑一轮 CI 收四平台数字、
  确认都能到 100%（或把够不到的行标注豁免）后再启用——
  agent 推荐先标定一轮（仓库被 `--fail-under-lines` 恒 99.x% 假红
  咬过，LL-057 同类）。
- 验证：CI 四格各出覆盖率数字且 ≥ 地板。

### S3 llvm-cov 安装改预编译包（已拍板，可直改）

- 目标：新增 `scripts/install_cargo_llvm_cov.sh`，照
  `scripts/install_wasm_pack.sh` 套路（官方最新产物、多平台 case、
  GITHUB_TOKEN 防限流、装到 `~/.local/bin`），替换 ci.yml 的
  `cargo install cargo-llvm-cov --locked`。
- 待定细节：脚本命名核对；闸门重排档决策四的"缺工具报错提示"
  文案同步指向新脚本。
- 验证：本机脚本跑通、`cargo llvm-cov --version` 可用。

### S4 python/native 胶水覆盖率扩面

- 目标：show-env 流程让 pytest / vitest 驱动时同步采集 rust 胶水行
  覆盖率（python、typescript/native 两 crate）。
- 待定细节：地板策略（先只采集看一轮数字，还是直接 100%——
  agent 推荐先采集，胶水从未被量过，第一天 100% 大概率红）；
  结构性不可达行豁免清单（unsafe 零拷贝块、async 错误臂等，按
  spec 铁律七逐条 `#[cfg(not(coverage))]` 标注 + 理由）；
  `coverage_gate.py` 多报告/按 crate 分别阅卷改造；spec 铁律七
  "工具作用域分离"条款修订（见 S6）。
- 验证：pytest / vitest 全绿且产出 rust 胶水行覆盖率报告。

### S5 wasm 胶水覆盖率 spike（先验证再立项）

- 背景：官方 WASM 覆盖率方案基于 wasm-bindgen-test，本仓库 wasm 是
  vitest 驱动，插桩计数在 wasm 内存里、无现成倒出机制（未验证）。
- 目标：spike 验证 vitest 下插桩 wasm 的 profraw 能否收集合并；
  结论（可行方案 / 不可行 + 替代路径如换 harness 或放弃 wasm 端
  rust 行覆盖）写回本档，再决定是否立项。
- 验证：spike 结论落本档 S5 节。

### S6 spec、闸门与账本收口（依赖 S1/S2/S4 结论）

- 内容：ci-matrix spec 铁律七修订（命令字面、工具作用域分离条款
  → 新口径）；`coverage_gate.py` 支持多报告；LL 登记（口径漂移
  假绿类 + 本轮新决策）；波及文档同步（LL-034：闸门重排档 T1/T2
  构成更新、CONTRIBUTING、scripts/README、Plan/测试规划）。
- 验证：`pnpm check:md` 绿、`pnpm check:meta` 绿、INDEX 与分片一致。
