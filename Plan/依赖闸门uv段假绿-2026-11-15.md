# 依赖闸门 uv 段假绿（2026-11-15）

级别：**硬**（闸门口径与自身实现矛盾——`check:outdated` 的 uv 段永远报 0 LAG）。
状态：**待点名修复**。发现于 change `drain-stray-profraw-in-tests` 的 task 7.4
（跑 `pnpm check:outdated` 后核对计数逻辑），不在该 change 的 diff 内，
也不在其 apply 态体检的"被触碰文件"范围内，故另立本档，不并入
`Plan/体检-2026-11-15.md` 的维度清单。

## 1 事实

- `scripts/versions/check_outdated.py:180-189` 的 `count_uv_changes()` 用正则
  `(Updating|Updated|Adding|Removing) \S+` 统计 `uv lock --upgrade --dry-run`
  的输出行数。
- uv 0.13.8（本仓 `check:outdated` 实际调用的版本）dry-run 的真实动词是
  **`Update` 与 `Add`**，不是 `Updating/Updated/Adding/Removing`。受控取证
  （`/tmp/uvverb`，钉 `idna==3.7` 后改钉 `3.6` 再 dry-run）：
  输出 `Update idna v3.7 -> v3.6`；新建锁时输出 `Add idna v3.7`。
- 该正则对 `Update idna v3.7 -> v3.6` 匹配失败（已实证：
  `re.search(r"(Updating|Updated|Adding|Removing) \S+", line)` → `False`）。
- 后果：只要工作区干净（无 `No lockfile changes detected` 之外的可计数行），
  uv 段恒为 0；真有可升级包时同样恒为 0 = 假绿。
- 本仓当场实例：`pnpm check:outdated` 打印
  `Update numpy v2.2.6, v2.4.6, v2.5.4 -> v2.2.6, v2.4.6, v2.5.5`
  （python 工程存在待升级包），末行却报 `SUMMARY: 0 LAG (all current)`、退出码 0。
- 单测未拦住：`scripts/tests/versions/test_check_outdated.py:527-529`
  用**臆造动词** `Updated foo v1.0.0 -> v1.1.0` / `Adding bar v2.0.0` 作夹具，
  与被测命令的真实输出不符，故该测试通过而闸门失效。

## 2 建议处置（等点名）

1. 改 `count_uv_changes()` 正则为 uv 真实动词集（`Update`/`Add`/`Remove`，
   兼容旧版 `Updating` 等可写作 `(?:Update|Updating|Add|Adding|Remove|Removing)`），
   并把单测夹具换成真实输出（含 `Update numpy v2.2.6, v2.4.6, v2.5.4 -> ...`
   这种"一行多版本对"的形态——一行只算一个 LAG 还是三个，需按 spec 口径定）。
2. 修好后 `pnpm check:outdated` 会首次报出真实 uv LAG（至少 numpy 一条），
   按 dependency-upgrade spec「apply 末尾体检与升级预授权」消化。
3. 归属建议：独立小 change（或点名直改 + 补单测），不塞进
   `drain-stray-profraw-in-tests`——该 change 的范围是 profraw 清扫与
   pytest 配置隔离，与本条无关。
