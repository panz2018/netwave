## 已确认问题（每条有出处）

1. **语言规则写了 3 遍**：`AGENTS.md` 开头"语言"节、同文件"文档语言与阅读
   入口"节、governance 元规则"教学式文档与类型标注"末段。违反自身元规则
   "同一事实 MUST NOT 跨层重复"。
2. **`Plan/README.md` 整段复述 `AGENTS.md` 的 Plan/ 生命周期**：四条 bullet
   几乎逐字相同，README 应只留表格+指针。
3. **铁律七塞了工具原理**：llvm-cov `--codecov` 与 `report` 路径的合并语义
   解释、"实测 950/950 恒差 6 行"属事件级事实，按[文档受众分层
   元规则](../openspec/specs/project-governance/spec.md#元规则-文档受众分层)
   应迁 lessons-learned 账本；宪法只留契约句+指针。
4. **`AGENTS.md` 书写规范节塞了配置级细节**：`.markdownlint.jsonc`、
   `.prettierrc.json`、`proseWrap: preserve` 选型理由、Biome 作用域——与
   CONTRIBUTING、根 `package.json` 三处重复；AGENTS.md 只该留
   "改 md 跑 `pnpm check:md`"一行。
5. **宪法混装两类规则**：铁律一~八、十二~十五是产品工程契约，
   元规则+知识产权是治理；557 行里治理约占 1/3。做文档类任务也得通读
   全部铁律，无关条款挤占专注空间。
6. **现成做法参照**：Anthropic Claude Code 最佳实践建议常驻指令文件保持
   精简、"变长就删"，细节移到按需读取的文件
   （[来源](https://www.anthropic.com/engineering/claude-code-best-practices)）；
   OpenSpec 官方同样主张 config context 只放指针。方向已对，执行不彻底。

## 已定裁决

- **瘦身手法取保守**：只删重复与错位内容，保留原句表述不重写压缩；每行
  diff 可追溯到已确认问题 1-4。
- **语言节去重**：顶部「语言」节保留三条；「文档语言与阅读入口」节删重复的
  语言 bullet，节名改「文档阅读入口」（全仓无 `AGENTS.md#` 锚点引用，改名安全）。
- **书写规范节压缩**：删 4 条配置级细节（`pnpm check:md` 聚合三项与
  `.markdownlint.jsonc`/`.prettierrc.json`/`proseWrap` 选型理由、Biome 作用域、
  `tsc --noEmit` 门禁时序、对称命令长段），替换为一行指针指向
  [CONTRIBUTING.md](../CONTRIBUTING.md)；其余 8 条书写行为准则原样保留。
- **`Plan/README.md` 形态**：删复述 [AGENTS.md](../AGENTS.md) 的生命周期
  bullet，只留一句指针 +「当前文件」状态表。
- **验收**：`pnpm check:md` 退出码 0 + grep 抽查重复事实已消；本批不设硬性
  行数上限（防再膨胀机制另议，见开放问题 Q6）。
- **流程**：不开 openspec change——不碰宪法，AGENTS.md 删节换指针有先例
  （归档 change `2026-10-25-add-dependency-upgrade-spec`）；
  实施待"实施"口令。
