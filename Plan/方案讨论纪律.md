# 方案讨论纪律 —— 治"反复返工"（临时纪律，未转正）

来源：近一个月会话复盘（49 会话 / 约 1060 轮，人工纠正 63 次）。
五类返工根因：看不懂术语、方案过复杂、越权执行、绕回已定裁决、不查现成方案。
本文件是**临时纪律**，默认不转正，见[转正判定](#转正判定)。

## 触发与豁免

- **触发**：话题存在两条以上可选路线，或会动 spec / 公开 API / 数据布局
  → 自动进入 grilling 轮次格式（一轮一问、问题编号、每题附推荐答案、
  找事实归 agent、拍板归人），禁止直接端大方案。
- **豁免**（直接答 / 直接干，不开拷问）：
  - 纯事实问答（"X 定义在哪""这命令怎么用"）
  - 琐碎改动（错别字、一行明显修复）
  - 执行已定裁决（人明确下令按某条裁决做）
- **关闭口令**：人说"别拷问了，直接给方案"→ 本话题退出轮次格式。

## 阶段解锁词表

讨论 → 落地共五档，**没说出口的动作一律不做**：

| 档位   | 解锁口令示例           | 允许的动作                                  |
| ------ | ---------------------- | ------------------------------------------- |
| 讨论   | "研究 / 讨论 / 捋思路" | 只读 + 只出文字，禁建文件 / change / commit |
| 写下来 | "写下来 / 记下来"      | 可写 `Plan/` 文档                           |
| 立项   | "建 change"            | 可建 openspec change                        |
| 实施   | "实施 / 可以实施"      | 可改代码                                    |
| 提交   | "提交"                 | 可 git commit（并入原"不主动 commit"规则）  |

## 最小方案默认

- 首轮方案 = **一个能独立验证、独立回滚的最小增量**；范围不够由人说"扩大"再扩。
- 方案必须附**"本次明确不做"清单**：agent 想顺手加的东西列出来给人砍，不许藏。
- 每个技术方案至少引用 1 个同生态成熟实现（项目 + 链接），
  或明写"无现成方案，理由 X"。没有出处不许端上来。

## 裁决台账

- **双写**：会话内每拍板一条，agent 立刻记"已定裁决"（决定内容 + 出处轮次）；
  提新方案前**必须先复述台账逐条对齐**，防止绕回。
- 引用人说的话必须给出处轮次；说不出出处 = 没说过，不许替人"记得"。
- **持久落点**：已立项 → `openspec/changes/<name>/decisions.md`；
  未立项 → 并入既有 `Plan/` 文件的"已定裁决"节；都没有才新建 `Plan/<话题>.md`。
- **不直写永久 spec**：`openspec/specs/` 与 lessons-learned 不接受台账直写。

## 转正判定

- **台账条目**：change 归档时集中判——agent 列出全部条目 + 建议去向
  （进 spec / 留 Plan / 删），人逐条圈定。**默认临时**：
  未获明确点头的条目随 Plan/ 清空消亡，沉默 = 不转正。
- **本纪律整体**：拆独立文件（即本文件），[AGENTS.md](../AGENTS.md) 只留
  3-5 行指针（指针属"实施"档，待口令解锁）；升格 governance spec
  须随某次 change 归档逐条判定，否则终态随 Plan/ 清空。
- 永久区入口只有一个：change 归档。

## 自检行

方案性回复末尾追加单行（普通问答不加，避免噪音）：

`🔍 大白话 ✓ | 出处 ✓（<项目/链接>） | 不做 N 项 | 台账 N 条已对齐`

- 某项没做到打 ✗ 并带原因（如 `出处 ✗ 无现成方案，理由：…`），不许空勾。
- 人扫一眼行尾即可判断 agent 有无偷工。

## 长会话止损

三条件**任一命中**即写交接笔记（含裁决台账）并建议开新会话，不许恋战：

- 单会话超过 40 轮
- 跨天继续同一话题
- 同一话题被人工纠正满 3 次

## 两层分治与工件门禁

- **对话层**：靠本文件的格式模板 + 自检行（结构性约束，比散文规则可靠）。
- **工件层**：`scripts/check_proposal.py`（待实施）扫在途
  `openspec/changes/*/proposal.md`（**排除 `archive/`**——已归档是既成事实，
  不拿新规矩回头要求旧文件），缺"现成出处""不做清单"两节即退出码 1，
  接入根 `package.json` 的 `pnpm check` 聚合。

## 待拍板：专家盲点追问（网传提示词改造）

网传四问提示词（无公认出处，已搜索核实）：①顶尖专家会做哪些我没要求的事；
②他们会从哪些最原始素材入手而非我整理好的；③他们会用什么方法和工具；
④除你我之外还有什么能证明结果正确；最后让 agent 改写题目以符合上述要求。

可行性判定（逐条对照本仓库既有机制）：

| 原问       | 现状                                                                   | 判定                                |
| ---------- | ---------------------------------------------------------------------- | ----------------------------------- |
| ① 专家盲点 | 无对应物——grilling 只问"没说清的"，不主动补"没想到的"                  | ✅ 真增量                           |
| ② 原始素材 | 已有更强：research 技能强制 primary sources + 宪法"机制断言先实证"     | ❌ 重复                             |
| ③ 方法工具 | 已有："方案先查现成做法" + 本纪律"现成出处必填"                        | ❌ 重复                             |
| ④ 独立证明 | 已有远强：铁律二独立真值（golden/闭式解/物理不变量）+ review 三轴 + CI | ❌ 重复                             |
| 改写题目   | 与"拍板权归人"冲突                                                     | ⚠️ 须改造为"增补建议，人圈定才生效" |

**建议**：只吸收①，改造为结构而非散文规则——grilling 每轮方案题的固定追问位，
或 proposal.md 固定小节；答案须具体到本任务的增补项（防泛泛套话注水）。
