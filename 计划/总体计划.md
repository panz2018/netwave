# NetWave 总体计划

> 一个频域散射矩阵（S-matrix）电路求解引擎，Rust 高性能核心 + Python/TypeScript 双端零拷贝绑定，
> 同一套程序同时服务 RF 与光学（光子学）。

## 1. 项目定位

### 1.1 要解决的问题
- 现有纯 TypeScript 实现（`RF-Touchstone`）用 `mathjs` 的 `Complex[][][]` 对象数组做计算，
  缓存不友好、堆分配严重，**大 Touchstone 文件（>50MB）直接卡死**。
- 只覆盖 Touchstone 解析，缺少 Network / Circuit 等完整体系。
- 缺少 Python 端能力，无法与 scikit-rf 生态互通。

### 1.2 核心定位
本质是 **频域散射矩阵线性网络求解器**：
- RF 的 S 参数与光子学的 S 参数在数学上是同一对象（端口上的复数相量 + 散射矩阵）。
- 因此引擎**域无关**：同一套核心可同时给 RF 和光学使用（对标 Lumerical INTERCONNECT 把 RF 算法适配到光学）。
- 只做频域、基于 S-parameter，不做时域仿真（区别于 circulax 等的时域方向）。

### 1.3 命名
- 仓库/品牌名：**`netwave`**（network + wave，域无关，短、稳妥、撞名风险低）。
- 核心类型命名**不出现 `rf` 前缀**，使用 `Port` / `Network` / `Circuit` / `Wave` 等中性词；
  参考阻抗 `z0` 作为端口属性，而非全局常量——这是让 RF 算法透明复用到光学的关键。
- tagline：*A frequency-domain scattering-matrix circuit solver for RF and photonics.*

## 2. 语言与架构选型

### 2.1 核心语言：Rust
决定性因素是 **双端（Python + TypeScript）+ 浏览器** 的零拷贝需求：
Rust 是唯一在三个目标上都有一线零拷贝绑定工具链的语言。

| 端 | 方案 | 零拷贝机制 |
|---|---|---|
| Python | PyO3 + `numpy` crate + maturin | Rust `Vec<Complex64>` → `PyArrayView`，包装裸指针，NumPy 共享内存 |
| Node | napi-rs | `ArrayBuffer` + `External` 后端内存，JS 端拿 `Float64Array` 视图 |
| 浏览器 | wasm-bindgen | 数据留在 WASM 线性内存，JS 拿 `new Float64Array(memory.buffer, offset, len)` 视图 |

对比 C++（Eigen 强但绑定工程成本高）/ C（ctypes 有拷贝开销），Rust 在绑定层与交叉编译发版上优势明显。

### 2.2 数据布局
统一用**交错复数扁平 f64**：`[re, im, re, im, ...]`，形状信息 `(nports, nports, nfreq)` 单独传递。
- 三个语言运行时都能零拷贝映射；
- 与 scikit-rf 的 `network.s`（`(freq, ports, ports)` complex128 ndarray）可直接互转。

### 2.3 大文件
Rust 侧用 `memmap2` + `rayon` 并行流式解析，根治大文件卡死；50MB s4p 预期几十毫秒级。

## 3. 仓库结构（Monorepo）

核心 crate 与两个绑定**必须同仓同步发版**（ABI 严格同步，避免版本漂移）。

```
netwave/
├── crates/
│   ├── netwave-core/        # Rust 核心：S/Y/Z/H/G 参数、Network、Circuit 求解
│   │   ├── touchstone 解析（memmap2 流式）
│   │   ├── 复数多维数组（ndarray + num-complex + rustfft）
│   │   └── 矩阵运算（faer / nalgebra）
│   ├── netwave-python/      # PyO3 + maturin → NumPy 零拷贝
│   └── netwave-node/        # napi-rs → Node 零拷贝
├── packages/
│   ├── netwave-wasm/        # wasm-bindgen → 浏览器（WASM 内存视图）
│   └── netwave-touchstone/  # 兼容层：旧 rf-touchstone API，内部委托 wasm/native
├── 计划/                     # 本目录
└── .github/workflows/       # 三平台矩阵构建（cargo-zigbuild / napi-rs CLI / maturin）
```

包名方案：
- crates.io: `netwave-core`
- npm: `@netwave/core`（napi）+ `@netwave/wasm`
- PyPI: `netwave`
- GitHub: `netwave`

## 4. 功能范围（对标 scikit-rf / SignalIntegrity）

- **Touchstone IO**：1.0 / 1.1 解析与写出，RI/MA/DB 格式，流式大文件。
- **Network**：S/Y/Z/H/G/T 参数互转，级联（`**` / deembed），renumber，mixed-mode（se2gmm/gmm2se），
  passivity 检查，时域变换（TDR / impulse response，FFT）。
- **Circuit**：多网络互连求解（`S = ([X^T]* - [C])^-1` 一类方法），auto_reduce 优化。
- **Calibration / Deembedding**（后续阶段）：EightTerm、TRL、IEEEP370 等。
- **Vector Fitting**（后续阶段）：有理拟合 + SPICE 等效电路导出。

算法**不重新发明**：照搬 scikit-rf 已验证的教科书算法，测试直接采用 scikit-rf 的测试数据做 golden test，
保证正确性且工作量可控。

## 5. 旧仓库处理

- `RF-Touchstone`（`rf-touchstone` npm 包）：README 指向 netwave；
  可选发一个薄封装版（内部委托 `@netwave/wasm`）维持 API 兼容，或直接归档 + deprecation 提示。
- 当前版本仅 `0.0.7`，兼容成本低。

## 6. 分阶段路线图

- **阶段 0 — 脚手架**：monorepo 结构、CI 三平台矩阵、`netwave-core` 空 crate + napi/PyO3/wasm 三绑定 hello world，
  验证零拷贝 buffer 往返。
- **阶段 1 — Touchstone 核心**：Rust 流式解析（memmap2+rayon）、交错复数数据模型、RI/MA/DB、1.0/1.1；
  用 scikit-rf 测试集做 golden test。
- **阶段 2 — Network**：参数互转、级联、renumber、mixed-mode、passivity、FFT 时域。
- **阶段 3 — Circuit**：互连求解、auto_reduce。
- **阶段 4 — 绑定完善**：Python NumPy 零拷贝、Node ArrayBuffer 零拷贝、浏览器 wasm 视图；
  旧 `rf-touchstone` 兼容层。
- **阶段 5 — 高级功能**：Calibration / Deembedding / Vector Fitting。
- **阶段 6 — 光学适配验证**：用域无关 API 跑通一个光子学 mzi/ring 示例，验证 RF/光学同源。
