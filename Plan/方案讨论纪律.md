# 方案讨论纪律 —— 治"反复返工"（临时纪律，未转正）

五类返工根因：看不懂术语、方案过复杂、越权执行、绕回已定裁决、不查现成方案。
本文件是**临时纪律**，默认不转正，见[转正判定](#转正判定)。

## 最小方案默认

- 首轮方案 = **一个能独立验证、独立回滚的最小增量**；范围不够由人说"扩大"再扩。
- 方案必须附**"本次明确不做"清单**：agent 想顺手加的东西列出来给人砍，不许藏。
- 方案先查同生态现成做法——规则唯一正文见
  [AGENTS.md](../AGENTS.md)「方案先查现成做法」，本文件不重述。

## 裁决台账

- **拍板即记**：会话内每拍板一条，agent 立刻记"已定裁决"（决定内容）；
  提新方案前**必须先复述台账逐条对齐**，防止绕回。
- 说不出裁决原话 = 没说过——不许替人"记得"，不许替人补拍板。
- **持久落点**：已立项 → 该 change 的 `design.md`「Decisions」节，
  不另建 `decisions.md`——同一事实只存一份正文；
  未立项 → 并入既有 `Plan/` 文件的"已定裁决"节；都没有才新建 `Plan/<话题>.md`。
- **不直写永久 spec**：`openspec/specs/` 与 lessons-learned 不接受台账直写。

## 转正判定

- **台账条目**：change 归档时集中判——agent 列出全部条目 + 建议去向
  （进 spec / 留 Plan / 删），人逐条圈定。**默认临时**：
  未获明确点头的条目随 Plan/ 清空消亡，沉默 = 不转正。
- **本纪律整体**：[AGENTS.md](../AGENTS.md) 只留 3-5 行指针（写指针属执行
  动作，须人点名）；升格 governance spec 须随某次 change 归档逐条判定，
  否则终态随 Plan/ 清空。
- 永久区入口只有一个：change 归档。

## 长会话止损

三条件**任一命中**即写交接笔记（含裁决台账）并建议开新会话，不许恋战
（数字为启发式，非精确阈值）：

- 单会话超过 40 轮
- 跨天继续同一话题
- 同一话题被人工纠正满 3 次
