## 延后项

### S5 wasm 胶水覆盖率（方案已定，待执行）

- 结论：可行。倒出机制有上游背书——wasm-bindgen 官方（0.2.93+，0.2.123
  起打通）与 NEAR/Hacken wasmcov 都用 minicov 把插桩计数留在 wasm 线性内存、
  宿主调 `minicov::capture_coverage()` 拷出 profraw，与测试 harness 无关。
- 稳定版可用性（本机 stable 1.100 / LLVM 23.1.5 实测）：wasm32 sysroot 不带
  `profiler_builtins`，`-Cinstrument-coverage`（稳定 flag）硬链它报 E0463；
  加 `-Zno-profiler-runtime`（runtime 由 minicov 提供）即通，但该 flag
  nightly-only，用 `RUSTC_BOOTSTRAP=1` 在钉死 stable 上解锁（二进制仍 stable，
  不装 nightly、不进日常路径）。minicov 0.3.9 bundled runtime = LLVM 23.1 /
  raw 格式 11，与 rustc 1.100 严格对齐。
- **待拍板（阻塞执行）**：`RUSTC_BOOTSTRAP=1` 解锁 nightly-only flag 是否
  违反 LL-020「nightly-only 禁用」铁律——LL-020 原文针对 `#[coverage(off)]`
  属性，本处是解锁编译 flag、源码不写 nightly feature，是否同性质需人裁定。
- 落点：node 侧、挂 `scripts/run/test_ts.sh`（rust 覆盖率链须同进程，与 native
  链同处一条；复用 `target-wasm` 独立 target dir，与 native 根 `target/` 不冲突），
  单独出 `coverage/coverage-wasm.json` + 独立地板。浏览器侧（`test_wasm.sh`
  的 `test:browser`）维持 TS-only——wasm 跑在 chromium Worker，profraw 须
  postMessage 回主线程再落盘，未验证，不在本轮。
- 实施步骤：① `typescript/wasm/Cargo.toml` 加 minicov（cfg 门控）+
  `#[wasm_bindgen] pub fn __cov_dump() -> Vec<u8>`；② 插桩构建：设
  `RUSTC_BOOTSTRAP=1`，`RUSTFLAGS` 取 `-Cinstrument-coverage`、
  `-Zno-profiler-runtime`、`--emit=llvm-ir`，走现有
  `CARGO_TARGET_DIR=../target-wasm` + wasm-pack；
  ③ vitest.wasm globalSetup teardown 调 `__cov_dump()` 写 profraw（threads 池
  串行，minicov 非线程安全，同 LL-092）；④ `llvm-profdata merge` +
  `llvm-cov report`（cargo-llvm-cov 不处理 wasm 符号，故手动：llvm-tools 的
  llc --march=<宿主架构> 编 .ll→宿主 .o）；⑤ 阅卷断言含 core/src 路径行且命中 > 0（LL-093）。
- 清理：wasm 覆盖率链前后各加 native 链同款两道——
  `python3 scripts/run/clean_stray_profraw.py`（倒出 profraw 到 target/ 外即判
  链未生效）+ `cargo llvm-cov clean --workspace`（清插桩产物防污染）。
- 编译期 C 编译器：minicov build.rs 硬编码 `cfg.compiler("clang")` 用 clang 编
  wasm32 C runtime（gcc 无 wasm32 后端、zig cc 对象 ELF machine 非标准均实测排除），
  用 wasi-sdk 自带的标准 clang（192MB tarball 解压到 `~/.local/opt/wasi-sdk`，无
  sudo）。波及面三处——新增 `scripts/install_clang.sh`（仿 install_binaryen.sh）、
  CI node job 加安装步、`test_ts.sh` 探测段探 wasi-sdk clang。
- 阅卷工具：`llc`/`llvm-profdata`/`llvm-cov` 取自 rustup `llvm-tools` 组件
  （写进 `rust-toolchain.toml` 的 components，rustup 自动装、零下载、与 rustc LLVM
  精确匹配），不进 check:outdated（随钉版走）。
- check:outdated 扩面：`scripts/versions/check_outdated.py` section 3（github-
  tarball/cargo 子命令）加 wasi-sdk 探测行——追最新 release，LAG 上报（同
  binaryen/wasm-pack 处理）。

### S6 vitest 三配置 functions / statements 阈值补齐（延后，本轮不做）

- 现状口径不一致（thresholds 维度）：native = lines+branches；wasm =
  lines+branches+functions；browser = 全四维。spec（ci-matrix）只强制
  `lines: 100`，functions/statements 非 spec 要求。
- 目标：三配置统一补齐到 lines+branches+functions+statements 全 100——
  native 补 functions+statements，wasm 补 statements，browser 已全。
- 验证：逐配置跑 `pnpm -C typescript test:<端> --coverage`，到 100 即钉；
  到不了 = 有结构性命中不到的函数/语句，按 LL-020 逐条 `/* v8 ignore */`
  标注豁免并附理由，禁硬编码行号。
- 波及面：若补齐后口径变化，同步核对 ci-matrix spec 覆盖率条款是否需把
  functions/statements 写进地板（当前只写 lines）。
