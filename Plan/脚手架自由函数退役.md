# 脚手架自由函数与 `Network` 类退役（终稿）

> **终稿。** 决策全部落定：`Touchstone` 已完整吞并 `Network`，**自由函数与
> `Network` 类全部退役，公开面只剩 `Touchstone`，且不新增任何 `Touchstone`
> 属性/函数**。`Arc` 机制落在 `Touchstone.s` 字段，用于 node 端 `s` 改零拷贝
> （双端零拷贝已拍板，见[拍板与核实结论](#拍板与核实结论)）。本页是立项
> （`opsx propose`）的直接输入；[待人工确认](#待人工确认)列出仅剩的人工决策项。

## 一句话目标

删除 `fill_pattern` / `read_element` 自由函数与整个 `Network` 类（core +
node + Python + 浏览器四端），零拷贝证据迁移到既有 `Touchstone.s`，
**不新增任何 `Touchstone` 公开面**。

## 已核实事实（带出处）

- **`Touchstone` 已含 `Network` 全部状态**：`core/src/touchstone.rs:197`
  字段 = `frequency`（`Frequency` 轴）+ `s`（交错 f64 主数据）+ `z0` +
  `nports`/`name`/`comments`/`version`/`parameter`。`Network` 是它的真子集。
- **core `Touchstone::s()` 借用零拷贝**：`core/src/touchstone.rs:767`
  返回 `&self.s`（`&[f64]`），不复制。
- **Python `Touchstone.s` 已是零拷贝活证据**：`python/src/lib.rs:428`
  用 `PyArray3::borrow_from_array(&view, obj)`，base object = pyclass 本身，
  `owndata=False`。写回证据无需 `read_element`：改视图后重读 `ts.s`
  （同一块内存）即可断言可见——**纯用既有 `s`，零新函数**。
- **Python `Touchstone.drop()` 只封存不清 buffer**：`python/src/lib.rs:606`
  仅 `self.1 = true`；`:344` 注释明说「already-acquired views stay valid
  (the buffer is never cleared; the pyclass owns it and numpy's base
  reference keeps it alive)」。**旧版担心的「drop 后视图悬垂」在
  `Touchstone` 上本就不成立，无需 `Arc`。**
- **node `Touchstone.s` 当前是拷贝**：`typescript/native/src/lib.rs:341`
  `Float64Array::from(self.core()?.s().to_vec())`。node `drop()` 同样只封存
  （`:487` `self.1 = true`）。→ 这是唯一真正的成本项（node 零拷贝，已拍板，见下文）。
- **浏览器 `Touchstone.s` 经拷贝 + 结构化克隆过界**：`core/src/touchstone.rs:1378`
  `f64_array` 把 `&[f64]` 包成 `Float64Array`，worker 回消息时结构化克隆
  再拷一次。浏览器本就无共享内存（transfer 模型），无悬垂问题。
- **`upload` 是 `Network` 专属**：`core/src/network.rs:141`、
  `typescript/src/index.browser.ts:110`。`Touchstone` 的浏览器数据入口是
  `fromBytes`（transfer，`core/src/touchstone.rs` 的 `call_namespace`
  `"fromBytes"` 臂）。**退役 `Network` = 全仓删除 `upload` 概念。**
- **`check_verbs.py` 三处绑定 `Network`**：`NETWORK_VERBS`（:36，含
  `fillPattern`/`readElement`/`drop`）、`BROWSER_ONLY = {upload}`（:83 段）、
  三端 `Network` 类校验段（:209–:242）。
- **`cross_compare.py` 主对比是 scaffold `.bin`**：`core.bin`/`python.bin`/
  `node.bin`/`wasm.bin`（来自 `fill_pattern`/`Network.fillPattern`/`readElement`）。
  **Touchstone 四端对比已独立存在**（`{end}_ts_{s1p,s2p,s4p}*.bin`，
  见 `scripts/cross_compare.py` 的 TOUCHSTONE PASS 段）——scaffold 对比与
  之冗余（见下文 scaffold 对拍核实项）。

## 拍板与核实结论

> 全部决策落定：node 零拷贝与 `fromData` 工厂由用户拍板；scaffold 对拍取代、
> `drop()` 措辞、浏览器往返 scenario 三项已由智能体核实定案（见下，写 spec
> delta 即可，无需用户）。

### node 与 Python 双端零拷贝（已拍板 = 保零拷贝）

用户明确「node 跟 Python 端都要零拷贝」。落地：core `Touchstone.s` 字段
`Vec<f64>` → `Arc<Vec<f64>>`，node `get_s` 改 `ArrayBuffer::from_external`

- finalize 回调 drop Arc clone（napi-rs 实证模式）。这是**改既有 getter
  实现**，`.d.mts` 签名仍是 `Float64Array`，不新增名字。Python `s` 已零拷贝
  （`borrow_from_array`，base=pyclass），无需动。浏览器无共享内存，`s` 维持
  克隆回传。

### 零拷贝活证据：派生数据回读（替代 `read_element`）

`read_element` 删除后，「同一块内存」用**既有派生面**证明，无需把视图传回
Rust。原理：`z`/`y`/`g`/`h`/`data` 全部基于 core 存储的 `s` 现算
（`core/src/touchstone.rs:852` `data` 的 `(S,RI)` 臂 `Cow::Borrowed(&self.s)`，
其余臂 `s_to_domain(&self.s,...)` 读活 `s`）。往返：

1. 取零拷贝视图 `view = ts.s`（Python `owndata is False`；node external）。
2. 改写视图某元素 `view[...] = x`（直接落进 core 内存）。
3. 读派生量 `ts.data("S","MA")`（或 `ts.z`）——core 从被改的 `s` 现算，
   该位置随之改变。
4. 把派生 MA/DB 换算回 RI，与第 2 步写入的 `x` 比对相等 → 证明写入落在
   core 同一块内存（独立验证通道，比单纯重读 `s` 更强：连「core 计算读穿
   到该内存」一并证）。

Python/node 双端各跑此往返；`cross_compare.py` 的「改元素→回读」对拍段据此
改写（输入改用真实 Touchstone）。

### 数据入口 = `fromData` 工厂（已拍板）

用户指出「构造器初始化就需要 s 的值，这就是 upload 的功能」。现状核实：浏览器
`Touchstone` 构造器是 **private**（`typescript/src/index.browser.ts`
「Construction IS parsing」），数据入口只有解析工厂 `fromText`/`fromFile`
（→`fromBytes` transfer）/`fromUrl`，**没有** Python/node 那样的
`new Touchstone(frequency, data, z0, parameter)` 裸数据构造器。

落地（用户拍板 = `fromData` 工厂）：三端绑定统一用 `Touchstone.fromData(...)`
静态工厂（参数 `frequency`/`data`/`z0`/`parameter`），与 `fromText`/
`fromFile`/`fromUrl` 凑成对称四件套（全是「从 X 造 Touchstone」的工厂）。`data` 经
transfer 移入 worker（worker 边界无共享内存，「零拷贝」即 transfer 移动
所有权），即 `upload` 的替代。`upload` 概念全仓删除。

**改名是 BREAKING（用户已认）**：node `#[napi(constructor)] new`（
`native/src/lib.rs:287`）与 Python `#[new] Touchstone(...)` 改为 `fromData`
工厂；本退役本就是 BREAKING 版本，捆绑进去。**Rust core 保留 `new`**
（Rust 惯用法，且 Rust 非跨端用户面）。「不新增公开面」按「改名非净增」
理解：删 `new`/构造器一个名、加 `fromData` 一个名，公开面总数不变。
spec「显式托管入口」requirement（`openspec/specs/api-contract/spec.md`）的
`Network.upload` 举例改写为「`fromData` 工厂 transfer 入 worker」；铁律八
scenario 同步。

**跨边界机制（实现要点）**：浏览器 `Frequency` 已是对象
（`index.browser.ts:154` `class Frequency`，`Frequency.fromF(...)` 造出）。
**用户层从头到尾只传 `Frequency` 对象**，与 Python/node 同签名，绝不手写
handle。handle 只是壳**内部**发 worker 消息时的传输细节（主线程与 worker 不
共享内存，`Frequency` 真身在 worker 的 core 表里，主线程壳只是带 handle 的
遥控器）。落地两处配合——

1. 壳 `index.browser.ts` 加 `static fromData(...)`：内部读 `frequency.handle`
   （壳自己读，非用户）连同 `data`/`z0`/`parameter` 发一条
   `touchstone`/`fromData` 消息，`data` 进 transfer list，
   返回 `Promise<Touchstone>`。
2. core `touchstone.rs` 的 browser `call_namespace` 加 `"fromData"` 臂：从 arg 0
   读 freqHandle，从表里取出已托管的 `Frequency`，调 `Touchstone::new`。
   取具体类型需给 `Resource` trait 加一个 core 内部 `as_any` 下转（把
   `&dyn Resource` 还原成 `&Frequency`，非公开面，仅 core 自用）。

`fromData` 工厂返回 `Promise`，天然避开 JS 构造器不能 `async` 的限制（无需
「未就绪壳」）。

### 智能体已核实定案（写 spec delta，无需用户）

- **scaffold 对拍被 Touchstone 对拍取代**：`cross_compare.py` 的 scaffold 段
  （`core.bin`/`python.bin`/`node.bin`/`wasm.bin`，源自 `fill_pattern`）与
  既有 Touchstone 段（`{end}_ts_{s1p,s2p,s4p}*.bin`，真实数据）覆盖同四端且
  后者更强——删 scaffold 段 + 四端 dump 脚本的 scaffold dump 行。**必做连带**
  （已核实 `cross_compare.py:120`）：anti-tautology 自检当前扰动
  `python.bin`/`node.bin`/`wasm.bin`，须改扰 `_ts_*` bin，否则自检失效。
- **`drop()` 措辞**（已核实 `memory-lifecycle/spec.md:90`）：「显式 `drop()`
  确定性即时」requirement 与其 scenario 全程以 `live_count()` 为见证，而
  `live_count()` 是 `Frequency` 专属——该 requirement 实为 `Frequency` scoped。
  `Touchstone.drop()` 只封存实例（访问报错），物理内存随包装器 GC/RAII 散场
  （`python/src/lib.rs:606` 仅置标志）。出 delta 把该 requirement 明确 scoped 到
  `Frequency`，并为 `Touchstone` 单列「实例封存即时，物理回收随最后持有者散场」。
  `live_count()` 维持 `Frequency` 专属，`Touchstone` 以访问报错为见证，不新增计数器。
- **浏览器往返 scenario**：常驻 worker 后主线程无 wasm，「视图 buffer 即 wasm
  `Memory.buffer`」物理不可能。zero-copy-roundtrip spec 的 wasm scenario 改断言
  transfer/结构化克隆路径的**数据正确性**（非零拷贝视图）。

## 已定（用户拍板 + 研究确认）

1. **`Network` 类整体删除**（core + 三端绑定 + 壳 + 测试），数据状态类唯一
   为 `Touchstone`。`fill_pattern`/`read_element` 自由函数一并删。
2. **不新增任何 `Touchstone` 公开属性/函数**——零拷贝证据全部复用既有
   `s`（读）+ `z`/`y`/`g`/`h`/`data`（派生回读）+ 构造器/工厂（写）。旧版
   `toBuffer()`/`buffer` setter 方案作废。
3. **node 与 Python 双端零拷贝**（用户拍板）：`Arc` 落在 `Touchstone.s`
   字段，node `get_s` 改 `from_external`；Python `s` 已零拷贝。浏览器无共享
   内存，`s` 维持克隆回传。
4. **数据入口 = `fromData` 工厂**（用户拍板）：三端绑定统一
   `Touchstone.fromData(frequency, data, z0, parameter)`，与
   `fromText`/`fromFile`/`fromUrl` 对称；经 transfer 移入 worker，替代
   `upload`。node/Python 的 `new`/构造器改名 `fromData`（BREAKING，捆绑本
   版本）；Rust core 保留 `new`。
5. **`drop()` 三端保留**（铁律十二同名；浏览器端它是 worker 表释放的唯一
   通道，删了必泄漏）。

## 零拷贝证据迁移（三端，全用既有面）

| 端     | 构造（数据入口）                             | 零拷贝/往返证据（既有面）                                                       | 新增面                |
| ------ | -------------------------------------------- | ------------------------------------------------------------------------------- | --------------------- |
| Python | `Touchstone.from_file` / `fromData(...)`     | `ts.s`（`owndata is False`）改写 → 读 `ts.data("S","MA")`/`ts.z` 换算回 RI 比对 | 改名 `new`→`fromData` |
| node   | `Touchstone.fromData(...)` / `fromFile`      | `ts.s`（external 零拷贝）改写 → 读 `ts.data("S","MA")`/`ts.z` 换算回 RI 比对    | 改名 `new`→`fromData` |
| 浏览器 | `Touchstone.fromData(...)`（transfer）/ 工厂 | `await ts.s`/`await ts.z` 经常驻 worker 往返，断言数据正确（无共享内存）        | 新增 `fromData` 工厂  |

写回证据不再需要 `read_element(view, idx)` 把视图传回 Rust：改零拷贝视图后，
core 的派生量（`z`/`y`/`g`/`h`/`data` 全基于活 `s` 现算）随之改变，换算回 RI
与写入值比对即证同一块内存（独立通道，比单纯重读 `s` 更强）。浏览器无共享
内存，往返只断言 transfer/克隆路径的数据正确性。
