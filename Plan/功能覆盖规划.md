# NetWave 功能覆盖规划

> 本文档在《总体计划.md》基础上，逐模块回答一个问题：**scikit-rf、SignalIntegrity、rf-touchstone
> 三个库的哪些功能要覆盖、哪些不覆盖、放在哪个阶段。**
> 原则：
> 1. 核心引擎只做"频域 S-matrix 线性网络求解"，主体就是 **Touchstone / Network / Circuit / Frequency
>    四大主类**及其函数，外加一个 `constants` 模块；
> 2. skrf 与 SI 只吸收**两者相同的交集功能**，各自独有的功能一律延后，以后按需再加；
> 3. GUI、仪器驱动、链路级仿真（眼图/COM）等外围能力不进核心 crate。

## 0. 三个来源库的角色

| 库 | 角色 | 与 netwave 的关系 |
|---|---|---|
| `rf-touchstone` (TS) | 旧作，仅 Touchstone 读写/格式转换 | **功能 100% 覆盖，但不做兼容层**（见 §1），旧包归档 |
| `scikit-rf` (skrf) | Python 事实标准，算法与测试数据来源 | **主干蓝本**：数据模型、算法、golden test 全部对标 |
| `SignalIntegrity` (SI) | 信号完整性全家桶（含 GUI/链路仿真） | **只取与 skrf 的交集**：两库都有的功能才进核心，独有功能延后 |

## 1. rf-touchstone —— 功能 100% 覆盖，不做兼容层（阶段 1）

**决定：不提供 `rf-touchstone` API 兼容层。**
旧库的计算 API 基于 `mathjs` 的 `Complex[][][]` 对象数组，与 netwave 的交错复数扁平
buffer（`Float64Array` 零拷贝视图）在类型系统上无法调和——强行兼容等于在 JS 层逐元素
搬运复数对象，零拷贝性能优势全部丢掉。

因此：

- netwave **重新设计干净的 JS/TS API**（`Network` 持有 `Float64Array` 视图），功能上
  覆盖旧库全部能力；
- 旧仓库 `RF-Touchstone`：README 指向 netwave，发 deprecation 提示后**归档**，不再发兼容版本；
- 迁移文档提供旧 API → 新 API 对照表（`matrix` → `network.s` 视图等）。

| 功能（必须覆盖） | 说明 |
|---|---|
| Touchstone 1.0 / 1.1 解析与写出 | Rust 流式重写，根治大文件卡死 |
| S / Y / Z / G / H 参数类型 | |
| RI / MA / DB 格式转换 | |
| 频率单位前缀（kHz/MHz/GHz…） | |
| `!` 注释、`#` 选项行、R（频率重采样）选项 | |
| 噪声数据行（`[Number of Noise Frequencies]`） | 解析保留，噪声计算延后 |
| fromUrl / fromFile / fromText / writeContent | 新 API 重新实现，非旧签名兼容 |

## 2. 主体范围：四大主类 + constants

**新项目的主体 = `Touchstone` / `Network` / `Circuit` / `Frequency` 四个核心类及其函数，
外加一个 `constants` 模块。** 功能取自 skrf ∩ SI 的交集（两库都有、算法同源），
任何一库独有的功能全部延后（见 §2.2 / §3.2）。

### 2.1 核心 crate 模块布局

| netwave 模块 | 对应 skrf | 对应 SI | 阶段 | 内容 |
|---|---|---|:-:|---|
| `constants` | `constants` | （散落各处） | 0 | 单位前缀、c/μ0/ε0、参数类型/格式枚举 |
| `frequency.Frequency` | `frequency.Frequency` | `FrequencyDomain.FrequencyList` | 1 | 频率轴、f_scaled、lin/log、插值重采样 |
| `touchstone` | `io.touchstone` | `Parsers.SParametersParser` | 1 | 1.0/1.1 流式读写、RI/MA/DB、噪声行解析 |
| `network.Network`（数据模型） | `network.Network` | `SParameters.SParameterNetwork` | 1–2 | `s`/`z`/`y`/`z0`/`port_names`/`frequency`，交错复数扁平布局 |
| `network::convert` | S↔Z/Y/H/G/T/ABCD | `Conversions`（S2Z/S2Y/S2T/ABCD2S/Z2S…） | 2 | 全参数域互转 + 参考阻抗 renormalize（SI `ReferenceImpedance`） |
| `network::cascade` | `**` / innerconnect / outerconnect | `Devices.Series` / `Parallel` 连接 | 2 | 级联、de-embed（T 参数链） |
| `network::ports` | renumber / flip / subnetwork | 端口重排 | 2 | |
| `network::mixedmode` | se2gmm / gmm2se | `Devices.MixedModeConverter` | 2 | RF 差分与光学平衡模式同源 |
| `network::checks` | passivity / reciprocity / causality | （IEEE P370 有，暂不取） | 2 | 奇异值法判无源性 |
| `network::ops` | interpolate / delay / port extension / split | `FrequencyDomain` DFT 工具 | 2 | |
| `time` | step/impulse response、TDR、DC 外推 | `TimeDomain` / `TDRWaveformToSParameterConverter` | 2 | rustfft |
| `circuit.Circuit` | `circuit.Circuit` + `Instance` | `SystemDescriptions`（数值求解部分） | 3 | `S=([X^T]Γ−[C])⁻¹[X^T]` 求解、auto_reduce |
| `circuit::elements` | （skrf 用 media 生成） | `Devices` 无源元件（SeriesR/L/C、ShuntZ、Tee、Thru、Transformer、Balun、Coupler、Mutual） | 3 | 内置元件库，光学耦合器/开关同源 |
| `math` | `mathFunctions` | `FrequencyDomain.DFTUtilities` | 1–2 | 复数工具、dB/线性、eigen 等 |

绑定层（阶段 4）：Python/Node/wasm 零拷贝 + CSV 便捷导入导出。

### 2.2 skrf 独有 → 全部延后（不进 v1 主体）

| skrf 模块 | 处置 |
|---|---|
| `calibration`（OnePort/SOLT/TwelveTerm/EightTerm/TRL…） | 延后。SI 虽有校准但算法体系不同，不构成"交集"；以后单独加 |
| `deembedding`（Open/Short/SplitPi…） | 延后，同上 |
| `vectorFitting` / `qfactor` / `taper` / `media` | 延后，SI 无对应实现 |
| `networkSet.NetworkSet` | 延后，纯统计便捷层，绑定侧随时可补 |
| `network` 噪声（noisy N-port） | 延后，与 SI Noise 一起评估（见 §3.2） |
| `vi/*`（VNA 驱动）、`plotting` / `notebook`、`io.citi` / `io.mdif`、`programs`、`data` | **永久排除**：仪器 I/O、绘图、小众格式与计算引擎无关；golden test 直接引用 skrf 测试集 |

## 3. SignalIntegrity —— 只取与 skrf 的交集

SI 的 App/GUI 层全部排除；Lib 层中**与 skrf 同功能**的部分已在 §2.1 合并吸收，
SI 独有的功能全部延后。

### 3.1 已在交集中吸收（见 §2.1 表）

`Conversions`、`FrequencyList`/`FrequencyResponse`/`DFTUtilities`、
`SParameters` 连接算法、`MixedModeConverter`、`SystemDescriptions` 数值求解、
无源 `Devices` 元件、TDR 变换。

### 3.2 SI 独有 → 全部延后

| SI 模块 | 处置 |
|---|---|
| `Noise`（NoiseAnalysis / NoiseTransferMatrices / Diff·CommonNoiseInserter） | 延后，与 skrf 噪声合并评估 |
| `ImpedanceProfile`（TDR 阻抗剖面） | 延后，TDR 之上的增值分析 |
| `ChirpZTransform` | 延后，小工具 |
| `Fit`（RLGC / PoleZero / LevMar） | 延后，与 skrf vectorFitting 一起规划 `fitting` 模块 |
| `Optical.OpticalCalculator` | 延后，作为光学验收示例（阶段 6）而非核心功能 |
| `SystemDescriptions` 网表文本格式 | 不做，Circuit 拓扑 API 已覆盖 |
| `App/*`、`Eye/*`、`Prbs/*`、Equalizer/CTLE/FFE、IEEE P370 COM/FER/QM、`Wavelets`/`Splines`、`Encryption`/`ResultsCache`/`TikZ`/`LaTeX`、`PySICppLib` | **永久排除**：应用层 / 时域链路仿真 / 行为级滤波器 / 标准合规套件 |

## 4. netwave 独有（三库都没有）

- **域无关设计**：`z0` 是端口属性而非全局常量，RF/光学共用一套 Network/Circuit。
- **三端零拷贝**：NumPy / ArrayBuffer / WASM memory 视图（见总体计划 §2）。
- **流式大文件**：memmap2 + rayon，50MB s4p 几十毫秒。
- **`@netwave/wasm` 浏览器一等公民**：skrf 无浏览器能力，SI 无 JS 生态。

## 5. 阶段映射总表（对总体计划 §6 的细化）

| 阶段 | 交付功能（来源标注） |
|---|---|
| 0 脚手架 | monorepo、CI 矩阵、三绑定 hello world、零拷贝往返验证、`constants` 模块 |
| 1 核心 IO | `Frequency` + `Touchstone` 1.0/1.1 流式读写（TS 全量 + skrf io.touchstone + SI Parser）、RI/MA/DB、噪声行解析 |
| 2 Network | `Network` 数据模型、全参数互转 + renormalize（skrf ∩ SI Conversions）、级联/de-embed、renumber、mixed-mode、checks、FFT 时域/TDR、interpolate/delay |
| 3 Circuit | `Circuit` 求解 + auto_reduce（skrf ∩ SI SystemDescriptions）、无源元件库（SI Devices） |
| 4 绑定完善 | Python/Node/wasm 零拷贝、CSV 导入导出、旧库迁移文档（**无兼容层**） |
| 5+ 延后功能 | Calibration / Deembedding / VectorFitting / 噪声 / media / taper / fitting / 阻抗剖面 / Chirp-Z —— 按需逐项加 |
| 6 光学适配验证 | 用域无关 API 跑通 MZI/ring 示例，验证 RF/光学同源 |

## 6. 覆盖统计（粗略）

- rf-touchstone：功能 **100%**，API **不兼容**（旧包归档）
- scikit-rf：v1 主体覆盖 `frequency` / `network`（计算部分）/ `circuit` / `io.touchstone` / `mathFunctions`
  ≈ 计算核心的 **~60%**；calibration/deembedding/vectorFitting/media 等延后；
  plotting/vi/data/小众 IO 永久排除
- SignalIntegrity：只取与 skrf 的交集（Conversions / FrequencyDomain / SParameters 连接 /
  MixedMode / Devices 无源 / SystemDescriptions 数值求解）；App、链路仿真、独有功能 0%
