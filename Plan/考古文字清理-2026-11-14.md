# 考古文字全仓清理（2026-11-14 人工裁决）

## 背景

`add-linux-arm64-binding-cells` 提案讨论中人工裁决：常驻文档与 CI 配置中的
考古文字一律清除——历史归因、"已标定/已废止/已重新启用"式叙述、指向
change 名 / LL 编号 / task 号 / CI run 号的指针全部删除。当前值只是当前
契约（如覆盖率地板现为 100，将来未必不变），注释与文档不预言未来；
追溯靠 git log。存量规模大（ci.yml 注释数十处开发文档指针与归因叙述、
spec 正文"原口径废止"式段落），不塞进 arm64 change，单开 change。

## 已定裁决（不再议）

1. 单开 OpenSpec change，建议名 `purge-archaeology-refs`；存量清理与
   防复发门禁在同一 change 落地（门禁标出的存量当场清掉）。
2. 防复发走门禁扩面，不在 `openspec/config.yaml` 的 apply/sync/archive
   加人工清理步骤（流程步骤是软约束会被跳过；最小规则原则：动作边界
   优于过程管束，已被门禁强制的规则只留命令一句）。
3. 门禁扩面两处：`scripts/check_comments.py` 扫描面加 `.yml`/`.yaml`
   （ci.yml 注释现无任何门禁覆盖，为真空区）；`scripts/check_md.py`
   增考古词模式（历史归因、口径废止式叙述；最终词表在 change 内定稿）。
4. 治理 spec「元规则 代码只写使用信息」的扫描范围随之从 `.rs`/`.py`/
   `.ts` 扩至 `.yml`/`.yaml`，Requirement 措辞与 Scenario 同步。
5. `scripts/coverage_gate.py` 的 floor 参数能力与地板 0 单测保留——
   它是通用阈值工具，0 只是合法输入值，不随 spec 流程删除而阉割。
6. lessons-learned 账本与 archive 为历史证据，新考古词模式拟沿用
   `check_md.py` 既有 ledger/archive 豁免先例；治理 spec 正文描述被禁词
   用描述性表达（既有 Scenario「治理 spec 反例不触发自身门禁」已定此
   口径）。豁免细节在 change 内确认。
