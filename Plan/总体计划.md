# NetWave 总体计划

> 一个频域散射矩阵（S-matrix）电路求解引擎，Rust 高性能核心 + Python/TypeScript 双端零拷贝绑定，
> 同一套程序同时服务 RF 与光学（光子学）。

## 项目定位

- 本质是**频域散射矩阵线性网络求解器**：RF 与光子学的 S 参数在数学上是同一对象
  （端口复数相量 + 散射矩阵），引擎**域无关**，只做频域、基于 S-parameter，不做时域仿真。
- 要解决的问题：旧纯 TS 实现（`RF-Touchstone`）用 `mathjs` 的 `Complex[][][]`
  对象数组做计算，大 Touchstone 文件（>50MB）直接卡死；缺 Network/Circuit 体系；
  无 Python 端能力。
- 命名：**netwave**（network + wave）；核心类型不出现 `rf` 前缀，`z0` 是端口属性
  （[铁律五](../openspec/specs/project-governance/spec.md)）。

## 已定案架构（正文已迁入 spec，此处只留结论与指针）

- **Rust 核心 + 三端零拷贝绑定**（PyO3/napi-rs/wasm-bindgen）：Rust 是唯一在
  Python/Node/浏览器三目标都有一线零拷贝绑定工具链的语言。
- **数据布局**：`(nfreq, nports, nports)` 交错复数扁平 f64，与 skrf `Network.s`
  逐字节相同——[铁律一](../openspec/specs/project-governance/spec.md)。
- **跨语言 API 面三层契约**（数据/计算/结构）、类式 API 形态、`upload`/`release`、
  z0 双动词、频率轴 f64 Hz、结构变更语义、worker 泛化分发——
  [api-contract spec](../openspec/specs/api-contract/spec.md)。
- **仓库结构与发布名解耦**：平铺 monorepo（core/python/typescript/testdata），
  三注册表主名一律 `netwave`，npm 单包 exports 条件分发——
  [workspace-layout spec](../openspec/specs/workspace-layout/spec.md)。
- **版本底线与 CI 矩阵**：Rust edition 2024 / Python ≥3.10 / Node ≥22——
  [workspace-layout spec](../openspec/specs/workspace-layout/spec.md)「版本底线」；
  矩阵见 [ci-matrix spec](../openspec/specs/ci-matrix/spec.md)。
- **包管理**：Python 一律 uv、Node 一律 pnpm（禁裸 pip/npm/yarn）；命令与坑见
  [CONTRIBUTING.md](../CONTRIBUTING.md) 与各子 README。
- **GPU（WebGPU/WebGL/CUDA）已评估，任何端都不引入**：f64 不支持违反铁律一、
  小矩阵负载不匹配、破坏零拷贝、生态冲突（论证全文见 git 历史本文件旧版）。
  WebGL 在 viewer 中只允许渲染不计算。将来重开 GPU 唯一合理场景是
  原生端大规模矢量拟合（Python 侧 CuPy），与浏览器无关。
- **旧库 `RF-Touchstone` 不做兼容层**：README 指向 netwave + 迁移对照表后归档
  （见[功能覆盖规划](功能覆盖规划.md)）。
- **多线程 wasm（wthreads + COOP/COEP）为可选增强**：运行时检测
  `crossOriginIsolated` 否则单线程回退；属阶段 3（见路线图）。

## 功能范围（对标 scikit-rf / SignalIntegrity）

主体 = **Touchstone / Network / Circuit / Frequency 四大主类** + `constants`。
骨架 = skrf ∩ SI 交集；旧库 rf-touchstone 功能 100% 覆盖是硬约束；单库独有功能
逐条显式批准。算法不重新发明，借鉴 skrf 已验证实现。
逐模块覆盖矩阵与延后清单见[功能覆盖规划](功能覆盖规划.md)。

## 分阶段路线图

**阶段模型铁则：地基从阶段 0 就是四端的。** 每个功能变更的 DoD = core 实现 +
三绑定同步暴露 + 四端测试全绿。

- **阶段 0 — 脚手架** ✅：monorepo、CI 矩阵、三绑定 hello world、零拷贝往返
  （已归档：`openspec/changes/archive/2026-09-27-phase0-monorepo-scaffold/`）。
- **阶段 1 — 测试基础设施**：`testdata/` 布局、`manifest.json` 契约、
  `gen_golden.py` 最小可用版 + 首批 parse golden 进 git、`golden-refresh.yml`
  周 CI、四端 golden harness。DoD = 一个 parse 用例走通 manifest → golden →
  四端断言全链路（含"假 golden 必须失败"自检）。
- **阶段 2 — Touchstone 核心**：Rust 流式解析（memmap2+rayon）、RI/MA/DB、
  1.0/1.1；skrf golden；三绑定同步暴露，四端 golden 全绿。
- **阶段 3 — wasm 性能定标与提速**：wasm 单线程基准 harness；50MB s4p 往返实测，
  把[铁律六](../openspec/specs/project-governance/spec.md)的 wasm"单独定标"落成
  阈值回写；提速候选 simd128 / 分块调优 / allocator / 可选 wthreads。
  DoD = 基线进 CI benchmark job，阈值写回铁律六。
- **阶段 4 — Network**：参数互转、级联、renumber、mixed-mode、passivity、
  FFT 时域（四端同步）。
- **阶段 5 — Circuit**：互连求解、auto_reduce（四端同步）。
- **阶段 6 — 绑定高级能力**：GIL 精细化、Node AsyncTask、wasm 视图失效强制机制、
  CSV 导入导出、旧库迁移文档。
- **阶段 7+ — 高级功能（按需逐项加）**：Calibration / Deembedding / Vector Fitting。
- **阶段 8 — 光学适配验证**：域无关 API 跑通光子学 mzi/ring 示例。
- **viewer（独立立项）**：Smith 圆图 + trace 图，只读视图渲染；发布名预留
  `@netwave/viewer`，插件 `@netwave/<功能名>`。

- [ ] Python GIL：所有计算入口 `py.allow_threads`；Node 大计算入口 AsyncTask
      （async 面清单）——阶段 6
- [ ] wasm 视图失效的具体强制机制与测试——阶段 6
- [ ] 频率轴非单调/重复频点的解析与拒绝规则——阶段 2
- [ ] `Frequency`/单位显示形态：`unit` 存 core 还是
      绑定层、`f_scaled` 命名与 property/方法形态、`Frequency` 独立类 vs
      `Network` 属性。倾向：unit 存 core 作元数据、`f_scaled` 只读派生

      绑定宏免费提供，计算全在 Rust）；明确不采旧库 RF-Touchstone 的
      setter 重算双份数据模式——阶段 1/2 design.md 定案
- [ ] 三端绑定壳省力化（动词 ≥10 个时兑现，预计阶段 4）：
      ① 仓库内小生成器读动词清单生成三端 `lib.rs` wrapper 段 + Python `.pyi`
      （pyo3-stub-gen，删手写 `netwave.pyi`）；② 一致性靠测试兜底：扩展 exports
      测试与 cross_compare，断言三端导出动词集合完全相等，漏绑即 CI 红。
      JS `.d.ts` 已由 napi build / wasm-pack 自动生成，零维护；动词 <10 个时手写壳最省
